# 量子技術がEV配送の需要充足と運用電力量に影響を及ぼす仕組みと成立条件

**EV配送の技術構造・パラメータ対応と専門家による概念モデルの精緻化**\
研究設計の記述基準日：2026年10月20日（概念モデル図・技術根拠を含む改訂原稿）

本リポジトリは、EV配送を社会技術システムの事例とし、古典技術を基準に量子技術の追加的な貢献可能性を検討する修士研究のコード・資料・保存結果を公開するものである。

現在の研究では、**技術名・技術方式を主たる分析単位**とし、IDEF0を用いて機能・ICOMを整理し、配送移動・電力消費を記述するパラメータへ対応付ける。専門家インタビューでは事前概念モデルを最初に提示し、技術による分解とパラメータ対応を求め、研究者の事前構造図と比較する。因果関係の有無・方向・強さや改善率は直接質問しない。

**公開リポジトリの主な実装・保存結果は、既存の限定的な定量実験に関するものである。** 更新後のシミュレーション案はインタビュー用の概念モデルとして扱い、実装済みの数値モデルとは区別する。専門家インタビュー、M0の正式な提示版固定、専門家別構造の取得、M1の作成は未実施である。

## 1. 研究目的・研究課題・仮説

### 研究目的

必要な配送需要の充足と、そのサービス提供に伴う運用電力量の低減を両立する観点から、量子技術が電気自動車を用いた配送に影響を及ぼす仕組みと、その効果の成立条件を明らかにする。

量子技術が必ず改善効果をもたらすことを前提とせず、効果が成立しない条件や逆転する条件も対象とする。

### 研究課題

量子技術のうち、どのような技術が、どのような仕組みを通じて、電気自動車を用いた配送の需要充足と運用電力量に影響を及ぼし、その効果はどのような条件で成立するか。

### H1：計算方法の相違による運用電力量への作用

量子計算は、古典計算とは異なる計画取得過程を通じて、配送・充電の運用に作用し、配送需要充足と運用電力量に異なる影響を及ぼし得る。

異なる経路の取得を成立の必須条件とせず、計画取得可否・取得時間等の相違も扱う。

### H2：電池性能の媒介効果

量子化学計算の成果が実用電池性能の改善につながる場合、電池性能の変化は車両・充電条件を通じて、配送需要充足と運用電力量に影響する。

材料計算の成果と、材料・セル・パックを経た実用電池性能の改善を区別する。

### H3：周辺条件による効果の変化

H1およびH2の効果の方向と大きさは、交通状況、運転特性、充電条件等の周辺要因との相互作用によって変化する。

上記の目的・問いはREADMEの採用済み表現、H1〜H3の本文はREADMEに記録された正式凍結版v1.0.1の文言を保持する。正式凍結資料の名称は `RESEARCH_OBJECTIVE_RQ_HYPOTHESES_FREEZE_20261014_v1_0_1.md` であり、公開リポジトリには同梱されていない。仮説の支持・棄却は未判定であり、今回のインタビューを仮説の直接的な因果検証とは位置付けない。

## 2. 対象システムと評価境界

都市部のEV配送について、計画取得・採用、車両出発、道路上の移動、駆動・電力管理、電池、荷渡し完了と記録を扱う。量子材料計算と実用化は、配送運用とは区別した外部の研究開発過程として参照する。既存実験の単一車両・合成需要・固定顧客集合を、一般的な配送システムの定義にはしない。

### 成果指標

| 指標 | 定義と注意点 |
|---|---|
| 期限内需要充足率 | 評価対象として固定した配送タスク集合に対し、実サービス完了時刻が各期限以内であるタスクの割合。未完了と観測欠測を区別する |
| 走行時の電池側正味DC電力量 | 同じ計量・集計境界における、牽引DC＋補機DC−電池が受け入れた回生DC。電池端子の正味計測と成分別集計を重複加算しない |

「運用電力量」は、上記の車両走行時の電池側正味DCを指す。対象区間には信号待ち・渋滞等の交通上の一時停止を含め、配送作業のための停車、充電、その他の待機は区別する。空調・電池温度管理・その他補機も、この対象区間内の消費を扱う。ログからの区間識別、計測条件、欠測処理の操作化・検証は別に必要である。

計算設備・量子計算機・データセンター、車外充電・充電損失、物流拠点、車両・電池製造の電力量は主要指標へ加算しない。この境界での比較を、物流全体やライフサイクル全体の電力量評価とはしない。

配送成果と電力量は併記し、未配送によって電力量が小さくなっただけの状態を省エネルギー効果と認定しない。

Version 0.2は13主変数・13接続関係・2効果修飾の構造基準版であり、すべての接続が経験的な因果関係ではない。比較・属性構成・指標定義・算術関係・条件付き仮定を区別する。

| 対象 | 現段階で保持する範囲 |
|---|---|

貨物割当、倉庫・積込、充電運用、安全制約等の固定・非展開方針を維持する。安全支援、量子センシング、交通・道路・気象技術を分類に記載しても、これらの条件や既存因果リンクを自動変更しない。

## 3. 研究方法

### 技術名による分解とパラメータ対応

国内外の政策・研究開発プロジェクト資料を技術候補の主要な抽出元とし、技術資料・原著等で名称と定義を確認する。政策目標、プロジェクト名、技術方式、材料、製品、開発目標、実施結果を区別する。国・事業への所属は出典情報であり、技術の種類階層ではない。

技術概念には恒久IDを付け、原表記・代表名・別名・略語を保存する。同義、上位・下位、構成、利用の関係を区別し、一つの技術を適用先ごとに重複登録しない。方式未詳の場合はその状態を保持する。

**技術を分解した結果は、配送移動または電力消費の何らかのパラメータに対応付ける。** 定義、単位、モデル上の位置までを記録し、直接対応しない上流技術は中間機能・量を介して整理する。説明できない対応は未確定として残し、技術名だけから数値・関数・改善率を補わない。

ここでいうパラメータは広義の対応量であり、係数、状態量、意思決定変数、観測値、予測値、評価出力を区別する。実際の気象条件と予測値、車両の真の位置と推定位置、実消費電力量と計測誤差は同じ量ではない。

### IDEF0の役割

[IDEF0の原典](https://nvlpubs.nist.gov/nistpubs/Legacy/FIPS/fipspub183.pdf)を参照し、機能、Input、Control、Output、Mechanismを整理する。技術は機能を実現する手段等へ対応付け、技術名の階層図とIDEF0機能図は区別する。技術分類上の親子関係、機能間授受、パラメータ対応、因果関係は異なる種類の関係である。名称・概念関係の管理には[SKOS](https://www.w3.org/TR/skos-reference/)を補助参照する。

提示表は**4列・1技術名1行**とする。第1列の位置IDで、全体図のどの上位層に属するかを追跡する。以下は形式を示す代表例であり、全技術一覧でも実装済み一覧でもない。

## 5. 既存定量実験と保存結果

### 計算工程と範囲

| 工程 | 実装・保存結果の対象 | 主な制限 |
|---|---|---|
| 入力 | OSM・PLATEAU・公的統計に基づく道路・合成配送需要 | 実注文データではなく、一部の生成過程・入力は公開配布に含まれない |
| 配送計画 | 固定顧客集合・単一車両の訪問順。目的は道路旅行時間最小化 | 車両間割当・充電・電力量を同時最適化していない。時間窓はサービス開始で判定する |
| 古典計算 | 3・4・5顧客の全列挙、25・99・125顧客のヒューリスティックとLP下界 | 大規模側の経路を大域最適解とは呼ばない |
| 量子計算 | 3・4顧客の理想状態ベクトルQAOA。正式定式化は補助変数なしのPUBO | 量子実機・誤り耐性量子計算の実行ではない。シミュレータ実行時間は実用量子計算時間の代用ではない |
| 車両走行 | 訪問順から道路経路・停車条件を構成し、SUMO軌跡を保存 | 保存条件は単一車両・背景交通なし。位置・速度の出力はセンサ誤差の表現ではない |
| 電池・電力量 | 容量20 kWh、比エネルギー180・220・250 Wh/kgの固定軌跡質量感度 | 量子材料計算や実用パック改善の結果ではない |

Controlled-DCは平坦路面、回生なし、補機除外、一括駆動効率0.9の限定モデルである。比エネルギーを変えてもSUMOの軌跡を再生成せず、同じ速度履歴に質量条件を与える。転がり抵抗は速度依存式の二条件であり、路面摩擦や濡れ・凍結を評価したものではない。既存の残量会計を、SOCに基づく停止・充電・再計画の実装とはしない。

詳細は[定量研究ガイド](docs/QUANTITATIVE_GUIDE.md)と[Controlled-DC凍結仕様](01_research_design/methodology/CONTROLLED_MASS_TO_DC_MODEL_FREEZE.json)を参照する。`net_DC_Wh`という出力名があっても、全成分を含む正味DCを評価したことにはならない。

## 7. 数値モデル更新への接続と評価

技術分解の結果から、将来的な更新候補を次のように分類する。更新後の数値シミュレーションの完成を、現在の概念モデル研究の必須成果にはしない。

| 区分 | 更新候補 |
|---|---|
| 対応表の更新 | 既存入力・変数で表現できる技術の名称・位置・対応を明確化する |
| 入力・設定の更新 | 根拠のある交通量・勾配・気象・車両属性等を接続する。値を渡すだけで有効になるとは限らず、受取処理を確認する |
| 計算・計量処理の追加 | 採用・出発・実完了、観測誤差、制御、補機・受入回生等について必要な仕様を定める |
| 未対応・保留 | パラメータ、関数、適用条件、データ等を特定できない技術は実装せず記録する |

### 表現・検証・妥当性

**Representation**では技術・機能・パラメータ・成果指標の区別を確認する。**Verification**ではID、単位、参照、境界、採否と実装の対応を検査する。**Validation**では専門家・文献と対象システムとの整合を検討する。これらを、ファイルのハッシュ一致や専門家の支持だけで一括して「検証済み」としない。

M0先行提示の誘導、対象者と政策資料の偏り、専門範囲・分解粒度の相違、研究者の採否判断は方法論上の限界である。パラメータの識別は数値校正・効果実証ではなく、量子・古典ハイブリッド計算の論理・物理資源と配送問題規模の定量的な対応も未確立である。

システムダイナミクス（SD）、ストック・フロー、SD–DES連携は現段階の独立した研究方法・完成要件ではない。既存の設計・実験・凍結資料は履歴として保持し、新しい構造の採用や数値実装は別の判断と版で管理する。
