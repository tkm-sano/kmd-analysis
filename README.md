# 量子技術がEV配送の需要充足と運用電力量に影響を及ぼす仕組みと成立条件

必要な配送需要の充足と、そのサービス提供に伴う電力量の低減の両立を扱う修士研究である。EV配送を社会技術システムの一例とし、古典技術を基準に、量子技術の追加的な貢献可能性と成立条件を検討する。配送シミュレーション、外部研究・データによる接続、システムダイナミクス（SD）、専門家レビューを研究全体の体系として位置付ける。

**現時点で本リポジトリが公開する主な実装・保存結果は、定量実験に関するものである。** 研究全体の目的・仮説・今後の方法と、実施済みの限定的な実験成果を区別する。本研究でいう「運用電力量」の主要な評価境界は、EV配送車両の走行時における電池側の正味消費電力量（DC）である。社会技術システムとしての分析範囲は、この電力量の集計境界より広い。詳細は末尾の「研究上の課題」に記載する。

## A. 目的

必要な配送需要の充足と、そのサービス提供に伴う運用電力量の低減を両立する観点から、量子技術が電気自動車を用いた配送に影響を及ぼす仕組みと、その効果の成立条件を明らかにする。

量子技術が必ず改善効果をもたらすことを前提とせず、効果が成立しない条件や逆転する条件も対象とする。

## B. 問い

量子技術のうち、どのような技術が、どのような仕組みを通じて、電気自動車を用いた配送の需要充足と運用電力量に影響を及ぼし、その効果はどのような条件で成立するか。

## D. アプローチ

### 1. 配送シミュレーション（計画取得・車両運行・電池・充電条件が配送需要充足と運用電力量に影響を及ぼす仕組み）

配送シミュレーションは、個別の技術・運用条件に対する結果を検討する**下位モデル**である。既存READMEの「研究の流れ」を以下に統合する。

実都市の道路制約、建物の分布、需要量を接続するため、OSM・PLATEAU・公的統計を組み合わせた。固定日の道路データをSUMO網へ加工し、建物と世帯・宅配統計から合成需要を作り、固定割当・時間窓・ODを持つ配送問題を構成した。

**オープンデータ取得 → 道路・建物・統計の加工 → 合成配送需要 → 古典／小規模QAOAの訪問順 → 保存SUMO軌跡 → Battery質量・DC電力量 → 対応比較・最終freeze**という流れである。建物の中間加工など未回復の工程もある。[取得方法・加工・計算を順に読む](docs/QUANTITATIVE_GUIDE.md#0-open-data-to-frozen-results)では、確認済み・再構成・推定・不明を分けている。

- **Path 1**：固定顧客集合の訪問順を道路旅行時間で最適化する。R0は3顧客、R1は4顧客で古典計算と理想QAOAによる計画取得を比較し、取得した訪問順をSUMOによる保存走行軌跡へ接続する。
- **Path 2**：20 kWh容量固定で180/220/250 Wh/kgをパック・車両質量に反映し、同じ保存軌跡のDC牽引電力量を比較する。Battery条件を仮定した下流の感度評価であり、量子材料計算による実用電池性能の改善を示すものではない。
- **対応比較・凍結**：取得・非取得を区別し、共通条件の保存結果を対応付けて最終freezeへ接続する。既存結果の数値と比較条件は後述の「結果と再現範囲」に保持する。

Notebook01〜03は合成入力の計算例、04〜05は正式保存結果の参照である。原データから全研究を一括再実行するパイプラインではない。

### 2. システムダイナミクスの設計（技術・運用・社会システムの時間的な相互作用）

本研究では、EV配送システムを、計算技術、車両・電池、交通・充電インフラ、配送需要、運用上の意思決定等が相互に関係する**社会技術システムの一例**として位置付ける。

量子技術の性能変化が社会技術システムの成果へ直接反映されるとは限らない。技術の導入・採用、既存の運用条件、他の技術との関係、システム内のフィードバック等を通じて、その影響は変化し得る。そこで、配送シミュレーションを下位モデル、SDを**上位モデル**として位置付ける。SDは定量実験の結果を単純に集計するものではない。

SDでは、以下を扱う。

- 配送需要と需要滞留
- 計画取得と運用判断
- 車両稼働と配送能力
- 電池性能と充電
- 交通状況
- 充電設備と電力供給
- 技術進歩と技術導入
- ストック・フロー
- フィードバック
- 時間遅れ
- 配送需要充足と運用電力量の関係
- 技術効果の成立条件と必要な能力水準

#### 経験的・統計的な接続層

配送シミュレーションとSDの間には、以下を用いる接続層を位置付ける。

- オープンデータ・公的統計
- 外部の学術研究
- 外部の実験・実証
- 経験式・統計モデル
- 交通・充電・電池等の外部モデル
- 専門家・事業者の知識
- 不確実性を明示した経験的仮定

この接続層によって、下位実験の結果と外部の証拠を、SDで使用できる関数・分布・パラメータ等へ変換する。出典、対象条件、単位、推定方法、適用範囲、不確実性を管理し、実測・計算結果と経験的仮定を区別する。外部データとの接続や定量校正が完了したという意味ではない。

#### SDシミュレーションの目的

必要な配送需要の充足と運用電力量の低減を両立できる条件を、技術・運用・社会システムの時間的な相互作用から明らかにする。

古典技術のみを用いる場合を基準シナリオとする。古典技術の将来的な進歩も考慮し、量子技術の導入による相対的な効果を比較する。特に、技術効果が成立・消失・逆転する条件や、必要な技術能力の境界を検討する。

SD Version 0は構造仕様案であり、定量校正や仮説の実証が完了したものではない。変数の内生化・外生化、関数形、時間尺度、パラメータは今後の検証対象である。

### 3. 専門家によるレビュー（配送需要の充足と運用電力量の低減の両立に必要な技術的条件）

定量実験、外部研究、SD分析の結果を基に、専門家によるレビューを実施する方針である。主な検討対象は以下である。

- 配送需要充足に必要な技術的条件
- 運用電力量低減に必要な技術的条件
- 計算・電池・充電の必要性能
- 古典技術に対する量子技術の追加的な貢献可能性
- 技術効果の成立・消失・逆転条件
- 技術的・運用的な制約
- モデルと仮定の妥当性
- 実用化の条件と不確実性

レビューは未実施であり、対象者・質問票・評価基準は今後具体化する。専門家判断を量子技術の効果の実証と同一視しない。SD構築時に必要な因果関係や関数形の知識を抽出するための専門家インタビューは、**採否未決定の別活動**である。

#### 研究工程の順序と反復性

基本的な実施順序は、**1. 配送シミュレーション → 2. SDの設計 → 3. 専門家によるレビュー**である。ただし、工程は一方向ではない。

- 配送シミュレーションの成果をSDへ反映する。
- SDで見つかった不足条件を定量実験へ反映する。
- 専門家レビューの知見を、定量実験とSDへ反映する。
- 必要に応じて各段階を反復する。

この順序は研究の実施順序である。下位モデル・接続層・上位モデルというモデルの階層関係とは区別する。

## E. 評価

### 1. モデルの表現の適切性・妥当性確認・検証

**モデルの表現の適切性**：研究対象のシステム、主要変数、影響を及ぼす仕組み、因果関係、制約、システム境界を適切に表現できているかを評価する。

**モデルの妥当性確認**：実測データ、既存実験、外部研究、専門家知識等との照合を通じて、モデルの構造や挙動が対象現象と整合しているかを評価する。

**モデルの検証**：数理式、状態遷移、保存則、単位、計算処理、再現性および実装の正当性を確認し、モデルが仕様どおりに動作するかを検証する。

### 2. 技術的到達段階の把握と古典技術を基準とした比較評価

古典技術と量子技術について、現在の技術的到達段階、実証状況、計算能力および適用可能な範囲を把握する。

そのうえで、古典技術のみを用いる場合を基準シナリオとし、量子技術の導入によって、配送計画の取得能力や電池性能を通じて配送需要充足と運用電力量にどのような差が生じ得るかを比較評価する。

古典技術の今後の進歩も考慮し、技術的効果の成立条件、必要な技術能力の水準および実用化に向けた制約を明らかにする。実証済みの成果、文献に基づく推定、将来の仮説的な技術条件を区別する。同一の需要・サービス水準・評価境界で比較し、未配送による電力量減少を省エネルギー効果として扱わない。

  → 定量実験を下位モデル、SDを上位モデルとし、両者を外部研究、オープンデータ、経験的・統計的な関係によって接続する研究体系を提案する。古典技術を基準とする比較により量子技術の条件付き効果を分析する。

- **作用原理・仕組み**：提案がどのような仕組みによって機能するのか。<br>
  → H1では計画取得過程から配送・充電運用への影響、H2では材料計算から実用電池性能を介する影響、H3では交通・運転・充電条件との相互作用を扱う。それらをSDの動的構造へ接続し、システム全体への影響を分析する。

- **研究方法**：どのような理論、モデル、分析、実験、調査を用いるのか。<br>
  → 古典・量子の計画取得比較、SUMOによる配送運行、Battery・電力量モデルを用いた定量実験を基礎とする。外部研究・公的統計等による経験的関係を接続し、SDによる動的分析と専門家レビューを組み合わせる。

- **評価設計**：何を指標とし、どのような比較対象・条件で評価するのか。<br>
  → 配送需要充足と車両走行時の電池側消費電力量を中心に、期限内需要充足率、全件サービス達成率、電力量、未処理・期限超過需要、配送完遂時間、条件変更による達成率差、必要な技術能力の境界値を評価候補とする。古典技術を基準とし、サービス水準と評価条件を揃える。

- **再現可能性**：方法、使用データ、前提条件を第三者が確認できるか。<br>
  → 既存定量実験では、入力条件、計算方法、保存結果、凍結記録、検証情報を管理している。今後の実験・SD・外部データ接続についても、出典、パラメータ、モデル版、実行条件、検証手順を管理する。ただし、全工程の一括再現が実現しているとは主張しない。

## 研究上の課題

### 対象電力量の範囲

本研究の評価対象は、**EV配送車両の走行時における電池側の正味消費電力量（DC）**である。配送走行区間には、信号待ちや渋滞による交通上の一時停止を含める。一方、配送作業のための停車、充電、その他の待機は走行区間から区別し、主要な走行電力量指標へ加算しない。「運用電力量」という表現も、この評価境界を指す。

#### 含める対象

- 駆動系の消費電力量
- 回生による回収電力量（正味消費から控除）
- 走行中の空調消費電力量
- 電池温度管理の消費電力量
- その他の補機消費電力量
- 信号待ち・渋滞等の交通上の一時停止中の消費電力量

空調・電池温度管理・その他補機も、上記の走行区間に属する消費を対象とする。成分別に積算する場合と、電池端子で正味電力量を計測する場合の整合を確認し、回生や補機を二重計上しない。

#### 対象外

- サーバー・データセンターの電力量
- 古典・量子計算設備の電力量
- 車外充電の電力量・充電損失
- 充電設備の付帯電力量
- 物流拠点の電力量
- 配送作業のための停車中の電力量
- 車両・電池製造、インフラ建設に伴う電力量

充電を配送・充電計画やSOC制約の中で扱うことと、充電時の電力量を主要な電力量指標へ加算することは別である。計算設備、電力供給、充電インフラ等の能力が配送成果に影響する仕組みを分析しても、それらの電力量を主要指標へ加算することにはならない。この境界による比較を、物流全体・社会全体・ライフサイクル全体の電力量削減の実証とはしない。

#### 既存の定量実験で扱っていない項目

既存の定量実験は、主として固定走行軌跡に対する限定的なDC牽引電力量を評価している。以下の7項目は、今後のモデル改善・データ接続・検証で扱う研究課題である。

- **回生制動による回収電力量**：減速・制動時に回収される電力量である。
- **空調消費電力量**：走行中の冷暖房・換気に必要な電力量である。
- **電池温度管理の消費電力量**：電池の冷却・加温に必要な電力量である。
- **その他の補機消費電力量**：照明、ワイパー、車載制御機器等の電力量である。
- **交通上の一時停止中の消費電力量**：信号待ち・渋滞停止中の空調・補機等による消費である。
- **道路勾配による駆動電力量の変化**：登坂・降坂による消費・回収電力量の変化である。
- **積載重量の変化による駆動電力量の変化**：配送に伴う荷物重量の減少等が駆動電力量に及ぼす影響である。

最後の2項目は独立した消費設備ではなく、**駆動電力量の変化要因**である。回生、補機、勾配、実際の積載変化等が既存結果へ反映済みであるとは扱わない。

評価対象・対象外の方針は上記のとおりである。走行・交通停止・配送停車・充電・その他待機をログから識別する規則、計測点と時間刻み、回生効率、補機の関数、勾配・積載データ、欠測の扱い、接続層とSDの集計整合は今後具体化・検証する。正式凍結文書や改善15項目の記録は保持し、今回のREADME採用表現・評価境界との相違を残したまま、研究者による今後の仕様整理へ接続する。
