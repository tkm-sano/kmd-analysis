## 目的

本仕様は、属性解決処理が構造確認用の値を適用する前に、欠損した`lanes`と
`maxspeed`をどのように分類するかを統制する。大田区版15の全件試行で観測した
45,749件の大量欠損を、すべて同じ許容可能な分類として扱うことを防ぐ。

重要度は属性ごとに決める。一つの明示された道路網用途区分において、ある属性へ
根拠のない値を使用した場合の影響を表す。OSM道路全体の一般的重要度ではなく、
道路の社会的・経済的重要性も意味しない。

本仕様は値そのものを許可しない。分類契約、証拠順位、許容処理、
実装と試験用固定データの合格後に限り分類を利用できる条件を定義する。

## 観測件数の来歴

本仕様に記載する件数は、設定定数ではなく版15の履歴観測値である。正本は
`03_data/metadata/acquisition/20260723_ota_ward_v15_resolver_dry_run.md`であり、
同文書が実行入力、設定ID、各SHA-256、出力成果物のハッシュを記録する。

| 観測値 | 集計単位と計算 |
|---|---|
| 統制対象候補26,220件 | v15の関係データ参照補完後に保持した道路IDの数 |
| 阻害項目46,056件 | 統制対象の判断が停止状態となった監査行の数 |
| 大量欠損45,749件 | `lanes`または`maxspeed`の出典値が実際に欠損した阻害行の数 |
| 規則・データ例外307件 | 大量欠損以外の阻害行の数、すなわち`46,056 - 45,749` |
| 除外されていたバス向け規制3件 | 全入力で`type=restriction:bus`かつ統制対象の右左折規制を持つ関係データの数 |

次の受理済み参照補完から件数を再集計しなければならない。これらを受入判定へ
固定値として埋め込んだり、正式実行の期待総数として扱ってはならない。

## 統制原則

1. 分類単位は一つの`(osm_way_id, attribute, profile)`組とする。
2. `lanes`と`maxspeed`は独立に分類しなければならない。
3. 低重要度の分類を、より影響の大きい用途区分へ流用してはならない。
4. 明示的または権威ある証拠を、低順位の構造確認用規則で上書きしては
   ならない。
5. 構造確認用代替値は`structural`用途区分の適格段階でだけ許容し、
   正式な研究結果には使用してはならない。
6. 証拠欠損、判定事実矛盾、不完全な分類被覆は停止状態とする。
7. 分類と値解決は別の判断である。重要度段階自体は属性値を与えない。
8. 較正対象道路または配送経路上の道路の特定などにより後から昇格した
   場合、以前の分類とすべての依存成果物を無効化する。

## 分析用途区分

| 用途区分 | 許容用途 | 重要度上の意味 |
|---|---|---|
| `structural` | 道路構造、接続性、通行権限、可視化の確認 | 属性別段階が許可する場合だけ承認済み代替値を検討できる。旅行時間、容量、配送に関する結論は禁止する |
| `formal` | 較正済み交通、配送評価、最適化比較 | 構造確認用代替値を禁止し、保持する全属性に統制済み証拠または正式仕様で許可された検証済みモデルを必要とする |

道路網を`structural`から`formal`へ変更する場合は再分類が必要である。
`structural`の分類を自動的に`formal`へ昇格してはならない。

## 母集団と部分道路網での役割

分類母集団は、関係データ参照補完受入判定条件に合格したOSM入力内の統制対象
候補道路集合とする。地域PBFや参照補完前の矩形抽出を直接母集団にしない。
参照補完済み入力のSHA-256が変われば、新しい分類実行を必要とする。

全候補道路は、最終SUMO道路網へ残さない道路を含め、次の
`subgraph_role`を正確に一つ持つ。

```text
final
topology_support
excluded
```

複数の真偽値による役割表現は禁止する。`excluded`道路も成果物へ残し、`lanes`を
`L0`、`maxspeed`を`S0`、`resolution_action=exclude`、
`value_state=excluded`、`resolved_value=null`とする。`topology_support`は
関係データ、接続、変換へ影響し得るため分類対象とし、基本段階を`structural`で
`L1/S1`、`formal`で`L2/S2`とする。高重要度の判定事実に該当すれば
`L3/S3`へ昇格する。

## 組・記録・改訂の契約

組は`(osm_way_id, attribute, profile)`とする。道路IDは正の10進文字列、
属性は`lanes`または`maxspeed`、用途区分は`structural`または`formal`とする。
一つの成果物には一つの用途区分だけを含め、除外道路を含む各組に有効な記録を
正確に一つ持つ。

安定した記録IDは次の形式とする。

```text
acr:<osm_way_id>:<attribute>:<profile>
```

記録は道路IDを数値昇順に並べ、同じ道路では`lanes`、`maxspeed`の順にする。
分類結果と属性解決結果は、同じ記録内の別オブジェクトとして保持する。

```json
{
  "classification_record_id": "acr:123456789:lanes:formal",
  "osm_way_id": "123456789",
  "attribute": "lanes",
  "profile": "formal",
  "classification": {
    "criticality_level": "L2",
    "selected_rule_id": "LANE-CRIT-006",
    "matched_rule_ids": ["LANE-CRIT-006"]
  },
  "resolution": {
    "resolution_action": "stop_unresolved",
    "resolution_rule_id": null,
    "value_state": "missing",
    "resolved_value": null
  }
}
```

属性解決オブジェクトは、構造化した`evidence_requirement`、`evidence_candidates`、
`selected_evidence_id`、`rejected_evidence_ids`、
`conflict_resolution_rule_id`、単位、確認来歴、停止コードも記録する。各候補は、
出典、値、単位、方向、区間、対象車種、期間、利用条件、出典ハッシュ、
対応付け信頼度を持つ。`evidence_requirement`は、証拠の要否、統制規則、最低権威
水準、説明を分離し、`L3`と`S3`では必須、それ未満では不要を明示する。
信頼度の尺度、閾値、同率時の処理を方針で固定するまで、値選択へ使わない。

成果物は変更不可な実行時点の保存物とする。判断を変更するときは同じ
`classification_record_id`で`record_revision`を増加させ、新しい
`record_sha256`、以前の`supersedes_record_sha256`、統制済み
`revision_reason_code`を持つ新しい保存物を作る。旧保存物を保持し、一つの保存物に
同じ組の複数有効な改訂版を含めない。

### 記録ハッシュの正規化と順序

`record_sha256`は、記録から`record_sha256`自身だけを除外し、RFC 8785の
JSON正規化方式で正規化したUTF-8バイト列のSHA-256とする。
オブジェクトのキー、空白、数値表現はRFC 8785に従い、配列順序は保持する。
明示的`null`と項目省略は異なるものとして扱い、スキーマが必須とする項目は
ハッシュ計算時にも省略しない。

記録は、数値としての`osm_way_id`昇順、`lanes`から`maxspeed`、
`structural`から`formal`、最後に`record_revision`昇順で並べる。現在の成果物は
単一用途区分であるが、将来互換性のため用途区分順序を契約に残す。

### 意味整合検査

JSONスキーマは局所的な形式と状態遷移を検査する。登録済みの
`validate_attribute_classification.py`は、記録間の失敗を`ACV`コードで
可能な限り収集する。派生記録ID、成果物と記録の用途区分一致、組と
証拠IDの一意性、母集団被覆、道路ごとの両属性、
`road_criticality.classification_rule_priority`に基づく規則選択、証拠参照、
完了状態、明示的に渡された改訂履歴、RFC 8785ハッシュ、正規化順序、
参照ファイルのSHA-256を検査する。
各記録の`source_artifact_sha256`は最上位の判定事実成果物ハッシュと一致し、
`classification_config_sha256`は最上位の分類方針ハッシュと一致
しなければならない。

検査処理は改訂や証拠の出典をディレクトリから暗黙探索しない。最上位
以外の出典は出典索引へ明示登録し、直前版の保存物は履歴として
渡す。これにより、同名だが無関係なファイルの誤採用を防ぐ。
コマンドライン処理は検出した失敗を一つで停止せず、`valid`、`errors`、
`ACV`コード、JSONポインター、メッセージ、期待値、実値を持つJSON結果として返す。

## 判定事実成果物

重要度分類処理は`attribute_classification_predicates.json`を消費し、OSM、経路、
較正設定、確認から判定事実を直接再調査してはならない。判定事実
成果物は母集団の道路ごとに正確に一記録を持ち、完全な母集団と出典のハッシュ、
排他的な`subgraph_role`、および英語正本に列挙した道路構造、車線と速度の意味、
採用済み配送経路、感度分析による昇格に関する各判定事実を保存する。

すべての判定事実値には、出典成果物の種別とSHA-256、出典内の記録位置、
導出規則IDが必要である。根拠のない真偽値は禁止する。

`subgraph_role_evidence`は真偽値ではなく役割区分の証拠であり、
`asserted_role`と同じ出典来歴を記録する。意味整合検査は
`asserted_role`と`subgraph_role`の一致を要求する。
`topology_support_reason`は常時存在し、`topology_support`では非空文字列、
`final`と`excluded`では`null`とする。

### 判定事実生成処理の契約

`generate_attribute_classification_predicates.py`は、関係データ参照補完済みOSM
XML、`predicate_source_registry.schema.json`に適合する出典台帳、
固定済みの`sumo_network.yml`方針の三つを明示入力とする。統制対象母集団は、
`highway`タグを持つすべてのOSM道路と、`topology_support`として明示登録した
`highway`タグを持たない道路だけで構成する。役割台帳はこの母集団を重複なく完全に
被覆しなければならない。

橋、トンネル、立体交差、車線の意味、速度の意味に関する判定事実は、
OSMタグから決定論的に導出する。較正、独立検証、
主要交差点、採用済み配送経路、感度分析に関する判定事実は、
ハッシュ登録された外部出典だけから得る。真と偽の両方に出典来歴を
保持する。確認済みの上書き判断は、その出典、位置、導出規則IDを
登録した場合に限り、一つの導出値を置換できる。

生成処理は不備を検出した時点で停止する。未受理の母集団、役割被覆の不足、
母集団外の外部ID、出典の欠損またはハッシュ不一致、スキーマまたは意味整合検査の
失敗、既存の出力先を検出すると停止する。書込みは原子的に行い、記録は
OSM道路IDの数値昇順とする。登録済み実データには母集団受入成果物と
設定版16以降を追加で要求するため、v15全件試行は正式実行の入力にできない。
合成した試験用固定データは`synthetic_fixture`の範囲を明示し、
実データ受理の証拠にはならない。

## 分類前の判定事実整合性検査

検査順序は、スキーマ、成果物と出典のハッシュ、道路IDの重複、母集団の完全被覆、
役割の列挙値、役割の矛盾、較正と検証の排他性、道路構造の矛盾、
属性別判定事実、分類規則の順とする。

次の場合は、優先順位が最も高い一致規則を選ぶ前に停止する。

- `excluded`と較正、検証、採用済み経路、感度分析による昇格、または
  主要交差点状態が併存している。
- `topology_support`に統制済みの保持理由がない。
- 同じ道路が較正と独立検証の両方
- 同じ道路が橋とトンネルの両方で、統制済み道路分割または個別確認がない

橋とトンネルの併存は、道路の分割または確認済み例外により正当になり得るため、
JSONスキーマで無条件の相互排他にはしない。判定事実の出典台帳は、この
裁定をハッシュで結び付けた確認済み上書き判断として明示する。その裁定がなければ、
意味整合検査処理は推測せず停止する。

方向別車線とバス・乗合自動車用車線の意味は併存できる。属性別判定事実が
異なる場合は、`lanes`と`maxspeed`で異なる段階を許容する。

## 車線数の重要度

車線数の重要度は、容量、方向配分、車線変更、交差点接続、
交通流への影響を扱う。道路の幾何学的重要性を意味しない。

| 重要度段階 | 機械的な意味 | 許容される属性解決 |
|---|---|---|
| `L0` | 統制済みの最終部分道路網判断で道路を除外し、道路網の生成に必要な構造維持用要素でもない | `excluded`を記録し、車線値を生成しない |
| `L1` | 選択用途区分が`structural`で、`L3`の判定事実がなく、許容された構造確認だけに値を使用する | 来歴と感度分析状態を伴う承認済みの構造確認用規則を適用できる |
| `L2` | 車線値が正式用の容量、交通流、接続、配送評価へ参加するが、`L3`の判定事実はない | 明示OSM、公的証拠、確認済み証拠、許可された検証済みモデルのいずれかが必要 |
| `L3` | 較正・検証区間、確認済み主要交差点進入部、複雑な方向・車線意味を持つ道路、または採用済み配送経路・感度分析により昇格した道路 | 自動代替値を禁止し、属性固有の証拠と必要な人手確認を必須とする |

### 車線数の分類順序

判定事実整合性検証の合格後、次の順序で最初に一致した規則が段階を決定する。

| 規則ID | 判定事実 | 重要度段階 |
|---|---|---|
| `LANE-CRIT-001` | `subgraph_role=excluded` | `L0` |
| `LANE-CRIT-002` | 較正区間または独立検証区間 | `L3` |
| `LANE-CRIT-003` | 車線数が統制対象の接続へ影響する確認済み主要交差点進入部、橋、トンネル、立体交差構造 | `L3` |
| `LANE-CRIT-004` | 方向別、可逆、時間帯別交通流、右左折車線、バス車線、乗合自動車用車線、競合する車線タグの解釈が必要 | `L3` |
| `LANE-CRIT-005` | 採用済み配送経路または登録済み感度分析結果が道路を昇格 | `L3` |
| `LANE-CRIT-006` | 用途区分が`formal` | `L2` |
| `LANE-CRIT-007` | 用途区分が`structural`で上記規則に一致しない | `L1` |

主要交差点進入部や構造維持用道路などの判定事実には、別の統制済み
成果物が必要である。名称または道路種別だけから暗黙に設定してはならない。
生成後または経路に基づく昇格は、正式用利用前に以前の分類を無効化する。

## 最高速度の重要度

最高速度の重要度は、自由流旅行時間、経路選択、到着時刻、
配送の実行可能性、電力消費計算への影響を扱う。観測交通速度を法的速度制限
として扱わない。

| 重要度段階 | 機械的な意味 | 許容される属性解決 |
|---|---|---|
| `S0` | 統制対象の最終部分道路網判断で道路を除外し、保持経路にも不要 | `excluded`を記録し、速度値を生成しない |
| `S1` | 用途区分が`structural`で、報告対象の旅行時間、容量、電力消費、配送結果に速度を使用せず、`S3`の判定事実がない | 承認済みの構造確認用規則を適用し、正式用ではないことを表示できる |
| `S2` | 速度が正式用の経路選択、旅行時間、電力消費、配送評価へ参加するが、`S3`の判定事実がない | 法的・行政的証拠、対応済みの明示OSM証拠、許可された検証済みモデルが必要 |
| `S3` | 較正・検証区間、条件付き・方向別・可変の速度表現を持つ道路、または採用経路・感度分析で昇格した道路 | 自動代替値を禁止し、時刻・方向・車種に適合する証拠を必要とする |

### 最高速度の分類順序

| 規則ID | 判定事実 | 重要度段階 |
|---|---|---|
| `SPEED-CRIT-001` | `subgraph_role=excluded` | `S0` |
| `SPEED-CRIT-002` | 較正区間または独立検証区間 | `S3` |
| `SPEED-CRIT-003` | 方向別、条件付き、可変、車種別、推奨、複数の速度表現の解釈が必要 | `S3` |
| `SPEED-CRIT-004` | 採用済み配送経路または登録済み感度分析結果が道路を昇格 | `S3` |
| `SPEED-CRIT-005` | 用途区分が`formal` | `S2` |
| `SPEED-CRIT-006` | 用途区分が`structural`で上記規則に一致しない | `S1` |

JARTICの観測旅行速度は較正または検証証拠であり、`maxspeed`へ
変換してはならない。

## 証拠階層

証拠は優先順位の前に適用可能性を評価する。別方向、別日、別車種区分、
別区間を参照する証拠は、適用可能な証拠と競合させない。

### 車線数

1. 整合する明示的な方向別OSM車線タグ
2. 方向配分が不要な場合の整合する明示的OSM総車線数
3. 方向・区間定義が適合する公的道路交通調査の車線項目
4. 照合済みの道路台帳証拠
5. 範囲限定し確認した権威ある画像
6. 選択用途区分で許可された事前登録・検証済み導出モデル
7. `L1`だけで許可する承認済み構造確認用代替値
8. 未解決

### 最高速度

1. 日付、方向、車種範囲が適合する法的・行政的交通規制証拠
2. 基準日と意味が適合する対応済み明示OSM速度タグ
3. 同じ区間・方向に対する確認済み公的機関証拠
4. 道路状態の仮定を検証した日付付きの法的導出
5. 選択用途区分で許可された事前登録・検証済み導出モデル
6. `S1`だけで許可する承認済み構造確認用代替値
7. 未解決

この番号は無条件の上書き順位ではない。競合は、法的・行政的権威、
基準日、区間と方向の一致、属性定義、利用条件への適合性、対応付けの信頼度
により解決する。解決できない競合は停止する。

## 属性解決の処理種別と状態

属性解決処理は、次の処理種別だけを出力できる。

| 処理種別 | 意味 |
|---|---|
| `adopt_explicit` | 対応済みの明示出典値を使用 |
| `derive_osm_rule` | 決定的なOSM意味規則を適用 |
| `adopt_external_evidence` | ハッシュ登録済みで適用可能な外部値を使用 |
| `apply_governed_rule` | 事前登録済みで代替値ではない導出規則を適用 |
| `apply_structural_placeholder` | 構造確認用途の`L1`または`S1`だけで適用 |
| `require_human_review` | 指定証拠が確認されるまで停止 |
| `stop_unresolved` | 許容可能な値がないため停止 |
| `exclude` | 別途統制された部分道路網判断により除外 |

対応する値状態は次のとおりである。

```text
explicit_osm
derived_osm_rule
authoritative_external
derived_validated_model
structural_placeholder
missing
unresolved
conflict
valid_but_unsupported
conditional
directionally_asymmetric
invalid
excluded
```

`resolved`だけでは値の由来が分からないため、有効な状態ではない。

許容する組合せは次のとおりである。

| 属性解決の処理種別 | 許容値状態 | `resolved_value` | 確認状態 |
|---|---|---|---|
| `adopt_explicit` | `explicit_osm` | 必須 | `machine_classified`または`reviewed` |
| `derive_osm_rule` | `derived_osm_rule` | 必須 | `machine_classified`または`reviewed` |
| `adopt_external_evidence` | `authoritative_external` | 必須 | `reviewed` |
| `apply_governed_rule` | `derived_validated_model` | 必須 | `machine_classified`または`reviewed` |
| `apply_structural_placeholder` | `structural_placeholder` | 必須 | `machine_classified`または`reviewed` |
| `require_human_review` | `missing`、`conflict`、`conditional`、`valid_but_unsupported`、`directionally_asymmetric` | `null` | `review_required` |
| `stop_unresolved` | `missing`、`unresolved`、`conflict`、`valid_but_unsupported`、`conditional`、`directionally_asymmetric`、`invalid` | `null` | `stopped` |
| `exclude` | `excluded` | `null` | `machine_classified` |

`invalidated`は現在の属性解決状態として使用しない。旧記録の置換は改訂
メタデータと変更不可な旧保存物だけで表現する。`L0/S0`は`exclude`だけ、
`L1/S1`は全処理、`L2/S2`と`L3/S3`は構造確認用代替値以外を許容する。
採用済み`L3/S3`は必ず`reviewed`とする。

## 各処理の責務

処理境界を次のように固定する。

```text
判定事実生成処理
    -> 分類に必要な統制済み事実を生成する
重要度分類処理
    -> criticality_level、selected_rule_id、matched_rule_idsを決定する
属性解決処理
    -> resolution_action、value_state、採用値、証拠、競合結果、
       確認状態、停止コードを決定する
意味整合検査処理
    -> 統合成果物と出典ハッシュを検証する
```

重要度分類処理は属性値を選択・補完せず、属性解決の処理種別も出力しない。
属性解決処理は
重要度分類処理結果、明示OSM値、登録済み外部証拠、許可済み検証モデル、
構造確認用代替値規則を入力とする。将来一つの実行入口へ統合する場合も、
オブジェクト契約と判断責務は分離したままとする。

## 用途区分別の必須成果物

| 成果物 | 処理上の役割 | `structural` | `formal` |
|---|---|---|---|
| 完全な判定事実成果物 | 重要度分類処理の入力 | 必須 | 必須 |
| 分類結果 | 重要度分類処理の出力・属性解決処理の入力 | 必須 | 必須 |
| 外部証拠成果物 | 属性解決処理の入力 | 参照時に必須 | 参照時に必須 |
| 構造確認用代替値規則 | 属性解決処理の入力 | 使用時だけ必須 | 禁止 |
| 分類・解決統合成果物 | 属性解決処理出力・意味整合検査処理対象 | 必須 | 必須 |

## 属性解決の判断順序

属性解決処理は、除外役割、適用可能な明示OSM値、決定的なOSM意味規則、適用可能で
確認済みの外部証拠、許可済み検証モデル、適格な`L1/S1` 構造確認用代替値、
人手確認、統制済みの未解決停止の順に評価する。重要度自体は値を生成
しない。

## 構造確認用代替値の適用条件

次の条件をすべて満たす場合に限り、構造確認用代替値を検討できる。

1. 用途区分が`structural`である。
2. 組が`L1`または`S1`である。
3. 適用可能な高順位証拠がない。
4. 競合、条件付き表現、未対応表現、方向の曖昧性がない。
5. 属性別の提供元母集団、出典ハッシュ、集約キー、除外条件、標本単位、
   方向処理、正規化、最小標本数、分布、採用値、最頻値の割合、
   同率時の規則が`sumo_network.yml`を満たす。
6. 採用値と規則IDを監査記録へ残す。
7. 正式用研究利用を引き続き禁止する。
8. 感度分析の状態を記録する。

一つでも満たさない場合は`stop_unresolved`とする。多数道路から得た最頻値は、
特定道路の値が正しいことの証拠ではない。

## 試験用固定データの契約

正式実行の分類前に、独立した試験用固定データで次を検証しなければならない。

- すべての車線・速度段階
- 二つの証拠出典間の優先順位と競合
- 完全組被覆と重複組
- 構造確認用から正式用への再分類
- 分類後の重要度昇格と依存成果物の無効化
- 許可・禁止される構造確認用代替値
- 未対応条件付き・方向別表現
- 除外と構造維持用道路の区別
- 決定的な繰り返し分類

試験用固定データの正解結果は、期待する組の記録内で分類オブジェクトと
属性解決オブジェクトを分ける。選択規則ID、一致規則ID、段階、処理種別、値状態、
解決済みの値、確認状態、失敗コードを含める。正式実行コードが自身の正解結果を生成しては
ならない。

`inputs.json`は事例索引ではなく完全な実行入力一覧とする。記録生成前に
停止する事例も対象組を持ち、OSM属性、判定事実、証拠候補、用途区分、
改訂状態を記録する。各正解事例は機械可読な表明と記録発行
方針を持つ。構成一覧の被覆情報は被覆IDと表明IDを対応づけ、段階と
事例分類の索引は手書きせず導出する。

異常系の試験用固定データIDは、失敗コードを含む`<code>-NEG-001`を維持する。
正常系、境界、再実行は単一失敗の証拠ではないため、それぞれ`AC-POS`、
`AC-BND`、`AC-REP`の名前空間を使用する。

`repeat`試験用固定データは、基準出力と再実行出力のハッシュ、バイト比較または
正規化内容の比較方法、正規化比較から除外する明示的なJSONポインターを記録する。
実行処理は指定した参照位置だけを除去し、RFC 8785に従う内容を比較する。
再実行以外の試験用固定データは
`repeat_assertion=null`を明示する。

`review.json`は、構造化した確認結果、証拠参照、確認者の識別情報、独立性宣誓、
観測ハッシュ、続行阻害指摘を保存する。`acceptance_allowed`は、
`collection_status=independently_accepted`、すべての必須確認が合格または非該当、
未解決の続行阻害指摘がないこと、という全条件から導出する。
研究責任者は2026-07-30に独立した人間による確認を省略すると決定した。この省略は
`acceptance_allowed=true`を意味せず、独立受理済みと報告してはならない。
実装順序から当該確認を外すが、固定ハッシュ検査、意味整合検査、
正式実行コードからの正解結果の独立性は引き続き必須とする。

正解結果は、正式実行の出力生成とは別の試験用固定データ作成手順で作成し、
可能な場合は正式実行の生成処理を作成した者とは別の者が確認する。
試験実行処理は正解結果ファイルのハッシュと出典仕様書のハッシュを検査する。
生成過程の独立性はJSON内容だけでは完全に証明できないため、作成者と確認の証拠を
試験用固定データの確認記録へ保持する。

## 現在の実装状態

本仕様は、母集団、組の識別情報、判定事実の契約、分類順序、
分類結果と属性解決結果の境界を固定している。次の機能は実装済みである。

- 4種類のJSONスキーマ
- 判定事実生成処理
- 成果物間の意味整合検査
- RFC 8785に基づく正規化ハッシュ処理
- 正式実行コードとは独立して作成した試験用固定データ
- 属性値を採用せず、重要度と規則識別子だけを出力する重要度分類処理
- 属性解決処理が分類結果を上書きしないことを保証する境界
- 正常、異常、境界、再実行、規則改訂の各試験

一方、明示値、外部証拠、検証済みモデル、構造確認用代替値から実際の採用値を
決定する属性解決処理と、受理済みv16母集団に対する全件統合実行は未完了である。
したがって、現在の実装済み分類処理だけを根拠に、正規化した地図データや正式な
SUMO道路網を公開してはならない。

独立した人間による試験用固定データの確認は、研究責任者の判断により省略している。
この方針は、独立受理済みであることを意味しない。固定ハッシュの検査、意味整合検査、
および正式実行コードからの正解結果の独立性は引き続き必須である。

最新の実装状態と阻害事項は、
[`RESEARCH_STATUS.md`](../../../RESEARCH_STATUS.md)、
[`current_issues_and_blockers.md`](../current_issues_and_blockers.md)、
[`confirmed_implementation_and_verification.md`](../confirmed_implementation_and_verification.md)
を正本として確認する。

## 次の実装順序

1. 明示値、外部証拠、検証済みモデル、構造確認用代替値から、採用値、証拠選択、
   競合結果、確認状態、停止結果を決める属性解決処理を実装する。
2. 固定した試験用データに対して重要度分類処理と属性解決処理を連続実行し、
   正常、異常、境界、再実行、規則改訂、証拠競合、代替値の各事例を検証する。
   実装出力に合わせて独立した正解結果を書き換えてはならない。
3. 受理済みの関係データ参照補完版16を入力とし、完全な
   `(osm_way_id, attribute, profile)`被覆を新たに生成する。版15の記録へ
   追記してはならない。
4. 構造確認用と正式用の成果物を別々に生成し、未解決の組を停止記録として保持する。
5. 意味整合検査に合格し、続行阻害項目が0件になった場合に限り、成果物を
   原子的に公開する。
