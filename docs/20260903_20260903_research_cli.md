`./research`は、既存研究処理工程、検証器、現行正本、研究ポータルに対するリポジトリの最上位の実行入口である。

### 道路網・配送地点の統合地図

`./research portal start`でポータルを開き、「研究で扱う交通ネットワーク」から統合地図へ移動できる。
地図は生成時点のスナップショットであり、正本・研究状態・配送地点数を更新した後は、リポジトリの最上位から再生成する。

```bash
PYTHONPATH=05_src .conda/bin/python -m traffic_simulation.visualization.render_current_map --overwrite
```

出力は`reproducibility/outputs/traffic_simulation/visualization/ota_ward_current_map.html`。
現行の正本の受入済みスーモ道路網、コマンド操作と共通のscoped 配送地点数、ポータルの研究工程を表示する。
ネットワークSHA-256・受入状態・道路件数・Stop件数を検査してから更新する。
閲覧にはLeafletと背景地図の配信先へのネットワーク接続が必要。
道路をクリックするとレーン別属性・接続道路・信号設定を確認できる。
詳細は隣接する`current_map_details/`から選択時に読み込むため、ウェブ文書を移動する場合は
このフォルダーも一緒に配置する。ポータル経由とウェブ文書直接閲覧の両方に対応する。

これは薄いorchestration層である。研究logicは元のモジュール、スクリプト、設定、データ構造、検証器、受入成果物に残す。コマンド操作は未解決の研究パラメーターを選択せず、受入状態を書き換えない。

## 2026-09-09の設計更新

今後の研究パイプラインは[最新B2C配送パイプライン](RESEARCH_PIPELINE_REFERENCE.md#b2c-pipeline-20260909)を設計正本とする。住宅向け宅配を主対象に、39,956候補地点から層化・重み付き非復元抽出し、顧客数nと複数乱数の種を実験パラメータにする。主需要単位は配送件数、基準は単一配送拠点、主指標はDFR_orders。OR-Toolsと制約なし二値二次最適化→量子近似最適化アルゴリズム→Qiskit Aerは同一問題例・共通必須制約を使用し、独立検証器を通して比較する。技術想定条件では顧客・需要・時間窓・道路条件を原則固定する。

旧記述との不整合は上記の最新方針を優先する。既存成果物の生成・受入事実は保持し、今後の設計採択を実装完了とは扱わない。

## 日常利用

```bash
./research commands
./research status
./research artifacts
./research network validate
./research routing inputs
./research pipeline full --dry-run
```

単一のコマンド 索引として`./research commands`を使用する。各コマンドの目的、実装利用可否、主要入力、主要出力を表示する。領域別構文は`./research <domain> --help`で確認する。

## 安全動作

- 読取り専用の状態確認・検証コマンドは、現行正本とその参照成果物を使用する。
- 構築／実行 コマンドは、本番実行器と上流判定基準が存在する場合だけ実行する。
- 実装不足または研究判断未解決の場合は、成果物を作らず`NOT IMPLEMENTED`を返す。
- 試行実行は実行せず、下位コマンド、入力、設定、出力、Git状態、timestamp、実行時間を表示する。
- 受入済み道路網と履歴実行を上書き対象にしない。
- `pipeline network`は受入済み道路網を再利用・検証する。下位処理工程が呼出側指定の一意な実行 識別子と分離出力保存先に対応するまで、新規道路網構築は利用不可とする。
- 本番段階が利用できない間、`pipeline full`は経路基準で停止し、下流段階を`SKIPPED`と報告する。

## 終了コード

`0`は実行または検査成功、`1`は失敗、`3`は依存判定基準閉鎖または本番実装利用不可を示す。利用不可の将来段階に対する試行実行は、実行を主張しない正常な検査なので`0`を返す。

下位コマンド失敗時、コマンド操作は失敗段階、コマンド、利用可能な記録情報、部分成果物の確認方法、次の診断コマンドを報告する。失敗を成功へ変換しない。

## 現在の実装境界

現行checkoutは、受入道路網の読取り専用検証、需要実装・受入対応付け検証、ポータル起動・検査、状態確認、成果物inspection、試行実行 orchestrationに対応する。本番の経路基準、共通配送問題例、古典最適化、制約なし二値二次最適化／量子近似最適化アルゴリズム、配送simulation、充足評価は利用できない。コマンド interfaceはこの境界を明示し、将来の正本実行器を日常入口の変更なしに接続できるようにする。
