`./research portal start`でPortalを開き、「研究で扱う交通ネットワーク」から統合地図へ移動できる。
地図は生成時点のスナップショットであり、正本・研究状態・Stopsを更新した後は、repository rootから再生成する。

```bash

```

出力は`reproducibility/outputs/traffic_simulation/visualization/ota_ward_current_map.html`。
current authorityの受入済みSUMO道路網、CLIと共通のscoped Stops、Portalの研究工程を表示する。
ネットワークSHA-256・受入状態・道路件数・Stop件数を検査してから更新する。
閲覧にはLeafletと背景地図の配信先へのネットワーク接続が必要。
道路をクリックするとレーン別属性・接続道路・信号設定を確認できる。
詳細は隣接する`current_map_details/`から選択時に読み込むため、HTMLを移動する場合は
このフォルダーも一緒に配置する。Portal経由とHTML直接閲覧の両方に対応する。

これは薄いorchestration層である。研究logicは元のmodule、script、config、schema、validator、受入成果物に残す。CLIは未解決の研究parameterを選択せず、受入状態を書き換えない。

## 日常利用

```bash
./research commands
./research status
./research artifacts
./research network validate
./research routing inputs
./research pipeline full --dry-run
```

単一のcommand indexとして`./research commands`を使用する。各commandの目的、実装利用可否、主要入力、主要出力を表示する。領域別構文は`./research <domain> --help`で確認する。

## 安全動作

- read-onlyの状態確認・検証commandは、現行正本とその参照成果物を使用する。
- build／run commandは、本番runnerと上流gateが存在する場合だけ実行する。
- 実装不足または研究判断未解決の場合は、成果物を作らず`NOT IMPLEMENTED`を返す。
- dry-runは実行せず、下位command、input、config、output、Git状態、timestamp、runtimeを表示する。
- 受入済み道路網と履歴runを上書き対象にしない。
- `pipeline network`は受入済み道路網を再利用・検証する。下位pipelineが呼出側指定の一意なrun IDと分離出力pathに対応するまで、新規道路網buildは利用不可とする。
- 本番Stageが利用できない間、`pipeline full`は経路基準で停止し、下流Stageを`SKIPPED`と報告する。

## 終了code

`0`は実行または検査成功、`1`は失敗、`3`は依存gate閉鎖または本番実装利用不可を示す。利用不可の将来Stageに対するdry-runは、実行を主張しない正常な検査なので`0`を返す。

下位command失敗時、CLIは失敗Stage、command、利用可能なlog情報、部分成果物の確認方法、次の診断commandを報告する。失敗を成功へ変換しない。

## 現在の実装境界

現行checkoutは、受入道路網のread-only検証、需要実装・受入mapping検証、Portal起動・検査、状態確認、成果物inspection、dry-run orchestrationに対応する。本番の経路基準、共通配送instance、古典最適化、QUBO／QAOA、配送simulation、充足評価は利用できない。command interfaceはこの境界を明示し、将来の正本runnerを日常入口の変更なしに接続できるようにする。
