# A〜D共通基盤 v1.1 準備時間0秒への改訂・検証

2026-11-11。今回の追加ユーザー指示を採用し、積込1800秒/便、顧客先作業120秒/地点を固定の研究仮定として維持し、帰着後準備のみ900秒から0秒へ改訂した。A〜D全てに共通適用する。時間変動モデルを導入しない。

## 現行条件・数式・実装

現行設定は`configs/toc_delivery/common_conditions_v1_1.json`、条件版は`AD-common-20261111-v1.1`。旧v1.0設定ファイルは保全し、共通loaderの参照先とSHA256 pinを新しい版へ切り替えた。旧条件の入力をv1.1として無言で扱わない。

- バース占有：`[load_start, load_start+1800)`、積込終了後に出発する。
- 帰着：`return = departure + Σ ceil(OD_duration) + 120×訪問地点数`。
- 第2便準備完了：`ready_v2 = return_v1 + 0 = return_v1`。
- 第2便積込：`load_start_v2 >= return_v1`。帰着直後の積込を許すが、出発には30分の積込が必要。
- 待機：`W = Σ(load_start−ready)/60`。積込作業・顧客作業を直接加算しない。

顧客作業は時刻伝播を通じた帰着、次便ready、72000秒の勤務終了判定にのみ使用する。距離・容量の目的へ加えず、詳細な変動モデルは作らない。積込時間はバース占有と待機の時系列計算に使用する。全時間値は実測値ではない。

共通検査器は既存の設定参照式を維持した。変更した実装は共通設定loader/pin、検査器の式注記、fixture、独立再計算・監査の旧900秒固定参照である。既存のB/C/Dアルゴリズム本体とD bridge本体は変更していない。D bridgeが0秒を受け取ることを回帰テストした。共通条件・入出力・実装計画・データ監査文書も更新した。
