### 小規模の再現コード

リポジトリrootで、A生成器と共通検査のみに依存する以下を実行できる。標準出力のみであり、既存成果を更新しない。Tの数値は環境・キャッシュで変化する。

```bash
PYTHONPATH=src PYTHONDONTWRITEBYTECODE=1 OPENBLAS_NUM_THREADS=1 \
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 python -B - <<'PY'
import time
from kmd_toc.common.models import load_problem
from kmd_toc.common.validation import validate_plan
from kmd_toc.baseline_a.construction import create_plan
from kmd_toc.baseline_a.independent import recompute
for case in ('ROAD_N6', 'ROAD_N20'):
    start = time.perf_counter()
    problem = load_problem('output/toc_delivery/ad_pipeline_20261112_route_v2/roads/inputs/' + case)
    plan = create_plan(problem, 'A2', 0)
    common = validate_plan(problem, plan)
    second = recompute(problem, plan)
    assert common.feasible and second['feasible']
    assert abs(common.D_km - float(second['D_km'])) < 1e-7
    assert abs(common.W_min - float(second['W_min'])) < 1e-7
    elapsed = time.perf_counter() - start
    print(case, common.D_km, common.W_min, elapsed)
PY
```

## 7. 正規化・比較可能性の判定

同条件AのプログラムTを採用すれば、人手TとプログラムTを混ぜるP0を**設計上は回避できる**。ただしAが人手を忠実に模擬したという意味にはならず、仮説の解釈は規則モデルを含む計算手法間比較に限定される。

同じ入力ごとのA由来D0/W0/T0と等重み1/3を採用する。全分母は正値で、主比較前に固定する。W=0の小規模例ではJを定義しないという採否規則も固定した。指定S1〜S3はAの第1便Wが正であるため、可行なAを得ればW基準は正になる。新Tがない現段階でJ値や仮説支持を報告しない。

三目的のスコアは事後評価であり、実行後のTを配送計画内部へ定数として足した最適化ではない。D/Wの探索・εと実測T/予算は分けて保存する。スコアだけでなく各絶対値・非支配関係を併記する。T0が短いほど遅い方法の相対ペナルティは大きくなるため、主結果に都合よく60秒等へ置換しない。未校正の人手Tを使ってDを有利にすることも認めない。
