## 3. 数理・計算構造

1. 各顧客単独配送の初期列を作る。
2. 原著式(8)の被覆LPをHiGHSで解き、式(12)の非負顧客双対πを得る。分割LPも別モードで検証する。
3. 価格付けは式(13)/(14)の距離−顧客双対を使う。古典全列挙は全容量可行な順列を列挙し、真の最小被約費用を得る。
4. AOAは位置one-hot、式(17)の容量ALiM、式(18)/(19)のliteral又は顧客添字補正版、式(20)のXYを使う。
5. XYは位置ブロックごとの厳密な行列指数で実装する。標準Xミキサーへ置換しない。
6. 訓練はone-hot部分空間での厳密なテンソル発展と有限shotsを使う。最終回路はRZ/RZZとXYブロックでQiskit上に構成し、Statevectorで実行・測定する。
7. 測定後に拠点固定・再訪・容量を検査する。内部拠点で分かれる可行walkは明示的に分割する。自由車両数の本参照では区間の距離/双対和が保存されるが、研究日列へは無条件に流用できない。
8. 真の負列だけを古典主問題へ追加する。AOA実行へ全列挙で得た列を補充していない。
9. 最終整数問題は式(7)の一度配送を満たす限定列分割である。別途全列集合の整数問題を診断用に解く。

古典oracleは小規模の診断であり、AOAの内部成功を偽装するfallbackではない。各AOA停止はAOA_NO_IMPROVING_COLUMNと記録し、全域非負性は別のoracleフラグへ保存した。

## 4. 原著表示式と補正案の検査

原著式(18)/(19)の位置ごとのu(u−1)は、one-hot下で0となる。顧客ごとの再訪禁止への補正案はΣ_i v_i(v_i−1)である。独立監査の反復系列(0,1,1,0)では、補正版のエネルギーはliteralより2高かった。これは添字の意味の差を数式・基底値で検証した結果であり、著者が補正を認めたという意味ではない。

式(20)の表示範囲どおりt=0も混ぜる構成と、t=0を定数として除く構成を実行した。4顧客、p=2、1再開始、80評価上限、4096shotsの同一条件で以下となった。

|t=0固定|重複項|固定拠点違反標本|可行標本率|
|---|---|---:|---:|
|あり|顧客添字補正|0/4096|35.767%|
|あり|原文literal|0/4096|32.715%|
|なし|顧客添字補正|1920/4096|36.597%|
|なし|原文literal|1837/4096|35.205%|

可行標本率は拠点固定だけでなく容量・重複・空walkを含む全判定後である。4行の標本率をもって補正の一般的優劣を主張しない。XYが保存するのは位置one-hotであり、容量・顧客一度訪問・固定されていない拠点を保存するわけではない。

容量ALiMのh+h²はh=-2で2、h=-1/0で0であり、容量以内でも負荷によって費用を変える。この順位変化を確認し、測定energyと真の被約費用を分離した。

## 6. 時間・資源の意味

参照系全体の秒数は実測であるが、全列挙oracleと全列整数解の診断も含むため、そのままA〜D比較用の計画取得時間Tとはしない。価格付け単体のAOA時間と古典全列挙時間はPRICING_COMPARISON.csvに別記する。古典全列挙は今回の小問題では約0.000052〜0.000722秒であり、AOAの優位性を示した結果ではない。

状態ベクトルだけなら15/18/21qubitは512 KiB/4 MiB/32 MiBであるが、Qiskitの多qubitユニタリ適用には大きな作業領域が発生した。主batchは620.741秒、最大RSSは11,246,484 KiB（約10.73 GiB）であった。これはTask A/Bと式監査を含む単一プロセスのピークであり、21qubitの生statevector又は12qubit単体のメモリと混同しない。これを生statevectorの必要量だけで説明しない。

主結果の回路深さは測定前の抽象ゲート深さであり、XYブロックを1ゲートとして数える。別監査の15qubit/p=2回路はrz/sx/x/cxへの全結合・最適化level0の分解で深さ6577、CX2992となった。実機結合へのルーティング済み深さでも最適合成でもない。論理深さ42を物理回路深さと称さない。
