# D価格付けの候補被覆と取得漏れの実測

## 対象・結論

2026-11-11の人工問題による検証である。Huangらの列生成＋AOAを維持し、既存回路を変更せず、候補領域のみを拡張した。旧最終snapshotの漏れは主として候補領域制限であり、全域負日列212本が旧領域には1本も含まれていなかった。拡張後は212本を3 seedとも取得した。しかし別の人工問題では測定による取り逃しが残った。AOAの失敗を改善列不存在の証明として扱わない。

全成果の根は `output/toc_delivery/d_improvement/run_20261111T061843Z/`（以下RUN）である。

## 旧結果の再現

旧出力 `output/toc_delivery/d_vehicle_day/run_20261111T033516Z/` を変更せず、旧 `scripts/run_vehicle_day_validation.py` をRUN/baseline_replayへ実行した。科学的フィールドは全件一致した。根拠はRUN/BASELINE_REPRODUCTION.json、baseline_replay/RESULTS.csv、AOA_PROVENANCE.csvである。

| 確認項目 | 再現値 |
|---|---:|
| 6顧客・1バースAOA最終LP | 3.75 km |
| 同・残存する全域最小被約費用 | −0.15 km |
| 同・限定列整数距離／全列整数距離 | 4.2／3.6 km |
| 古典列生成LP閉包後の整数gap | 0.3 km |
| 主6ケースの追加負日列 | 760本 |
| 新しい測定便を含む／既知測定便のみ | 709／51本 |

760本は異なる日列の追加数であり、760個の独立な量子意思決定でも、量子計算のみで発見された日列数でもない。51本は既知便の時刻・組合せを含む古典完成器の寄与である。

## 探索構造と除外されるもの

1. 顧客候補：旧方式は双対上位3顧客と反復依存アンカーの道路距離近傍3顧客である。それ以外の顧客組合せを含む便が除外される。
2. 量子変数：位置3、固定拠点を除く2位置×4ノード＝8量子ビットである。AOAは候補顧客の選択と順序を決める。日列の車両・時刻は量子変数ではない。
3. 測定・復号：既存 `column_generation/aoa.py` を使用する。one-hot、容量超過、重複訪問、空の出力等は同コードのreason_countsに保持する。feasible_shotsは符号化上可行なショット数であり、全顧客配送計画の可行率ではない。
4. 完成器：生成便を少なくとも一つ含む日列だけを列挙する。相手便はsingleton、現在のRMPにある便、今回生成した便に限る。未生成の相手便を必要とする日列は除外され得る。
5. 可行性：旧 `make_day` と独立 `validate_day` により容量・便接続・勤務時間を確認する。全体バース排他は主問題で扱う。
6. 被約費用：完全な日列について顧客・車両・バース・ε制約の双対項を含めて再計算する。単独便のproxyエネルギーとは区別する。AOAのproxyは車両・バースの双対価格を直接量子回路に含まないため、真の価格付けの近似候補生成である。
7. 重複排除：同じ入力・車両・便順・積込開始時刻の日列を除外する。負列は1反復20本まで追加する。未追加の残りを探索漏れと混同しない。

今回の完成器は事前全列カタログの索引を使う独立実装である。同じ便集合に対する旧完成器との日列ID集合の一致も検証した。カタログ全列の可行性を前検査したため、「完成器で失われた可行列」「完成後不正列」は0である。これは未測定の便や未定義の候補領域が存在しないという意味ではない。

全域古典oracle、縮小領域古典全列挙、AOAは同じ双対・可行性・日列被約費用・重複規則を用いる。AOAへoracle列を注入しない。値の根拠はRUN/coverage_attempt03/COVERAGE.csvと各snapshot JSONである。

| 旧AOA終了時・D | 212 | 0 | 212 | 212／212／212 |

候補被覆率は領域内負列数／全域負列数である。取得率は測定から完成された異なる負列数／領域内負列数である。旧終了snapshotは候補被覆0%から100%、拡張AOA取得率100%となった。旧領域の取得率は分母0のため未定義である。

holdoutでは候補被覆100%でも取得率99.28%、98.56%、98.56%であり、平均98.80%、範囲98.56～99.28%である。測定由来の未取得は24／48／48本である。最小被約費用の列は3 seedとも取得できた。これは有限回の実測であり、成功確率の一般的下限ではない。全域負列0のsnapshotは両比率ともnullとした。

同じ旧終了双対を使った独立時間計測はRUN/SNAPSHOT_BENCHMARK_attempt02/TIMINGS.csvである。全域古典oracleは約0.0011秒、拡張領域の古典全列挙は0.0045秒、拡張AOAは0.1670～0.1687秒で、いずれも212本・最小被約費用−0.15を返した。前処理カタログ0.623秒は別記録である。量子側の時間にはproxy変換・角度探索・測定・完成・被約費用・重複判定を含めた。小さなカタログ済み人工問題での計測であり、S1の時間比や量子優位性の根拠にはしない。

旧終了snapshotの拡張では7領域、計28,672 final shots、最大8量子ビット、論理回路深さ21であった。212本取得しても1反復20本だけを追加し、192本はその反復のbatch上限で未追加となる。既存負列の重複は0である。rawショットの不正・可行内訳は各quantum.result.reason_countsで確認可能であり、列数とショット数を混合しない。

## 更新・未探索領域の管理

旧領域から始め、未被覆ペアを最も多く含む三つ組を追加する。同数はID順である。更新は全域oracleの負列位置を使用しない。双対snapshotのSHA-256＋領域＋符号化版を探索キーとする。各反復で新しい双対に対して再評価する。RUN/REGION_COVERAGE_LEDGER.jsonには実際の領域重複0、未被覆ペア0を記録した。

未訪問の三つ組は残り得るが、Q=2・単位荷量の人工問題では全ペア被覆により全可行単独便が少なくとも一領域で表現できる。一般の容量・長い便にはこの性質を適用できない。測定不取得、相手便制限、異なる双対snapshotを別の未完了状態として扱う。

同じ旧終了双対・同じ相手便集合で比較した。根拠はRUN/coverage_attempt03/MACROS.csvとMACRO_*.jsonである。

すべての可行な展開について距離・荷量・双対利益の保存を検証した。内部距離をマクロ入口コストに組み入れ、需要と双対を和にする既存contractを再利用した。区間の更新で可行便の種類が変わり、94本を回復した例がある一方、118本は残る。固定向き区間は反転・内部順序・分割先を表現しない。表はQ=2の検証であり、長い50地点便のマクロ探索を実装・検証した結果ではない。

RUN/MACRO_VEHICLE_TRIP_PLACEMENT.jsonでは、この94本がV0・V1それぞれ第1便28本、第2便19本に配置できることも確認した。マクロに固定車両所有は与えていない。

## 判定

候補被覆の測定と拡張機構はGO（有限人工領域内）である。AOA取得能力はCONDITIONAL GOであり、候補拡張と複数seedでも取り逃しが残る。全域の改善列不存在証明はHOLDである。原著の列生成・ALiM・XYの根拠は[Huangら III-B、III-C](https://arxiv.org/html/2503.17051v1)であり、本報告の領域更新・日列拡張は原著実装済み機能とは称しない。
