# Dの段階的拡張とS1接続判定

## 総合判定

有限Q=2人工問題での候補拡張・共通古典対照・整数gap分析は完了した。8顧客2車両、10顧客3車両まで実行した。S1はHOLDである。今回のコードは全列カタログを完成器にも必要とし、S1への直接接続を認めない。S1～S3の需要・OD・運行条件・RQ・仮説・A～C・旧実験を変更していない。

出力根：`output/toc_delivery/d_improvement/run_20261111T061843Z/`（RUN）。各stageのEXECUTION_MANIFEST.json、SOURCE_SNAPSHOT、INPUT、CSV、JSON、watchdog記録が来歴である。

## 人工問題と計測条件

V1は4～6顧客、2車両、1／2バースの旧検証問題を再現した。新規統合は5／6顧客B1と別距離行列holdout6である。V2は8顧客F2B1/B2、10顧客F3B2である。全て単位荷量・容量2個、積込120秒、準備120秒、地点作業120秒、非対角移動120秒、勤務0～1680秒、時間刻み120秒という明示的な人工条件である。道路実績や研究用配送車両の仕様ではない。距離行列は非対称であり入力JSONに全保存した。

Python3.12.11、Qiskit2.1.1、NumPy2.3.1、SciPy1.16.0、HiGHS1.8.0を既存の隔離環境で使用し、依存導入・更新はしていない。OPENBLAS_NUM_THREADS=1、OMP_NUM_THREADS=1である。状態ベクトルはCPUであり、量子実機測定ではない。

## 停止・資源管理

事前仕様は `configs/toc_delivery_d_pricing_improvement_v1.json` である。CG40反復、AOA800呼出し／ケース、列120,000本、量子ビット16、IP50,000ノード、RSS1536MiB、独立stage300秒を安全上限とした。成功stageでは安全打切りは0であり、有限候補領域で新しい負列がなくなった状態で終了した。AOAの終了に全域証明ラベルを付与していない。外部の全域古典oracleの診断では最終負列不存在を確認した。

開発中の失敗も保持した。coverage初回はソースsnapshot保存の絶対パス処理、attempt02はW proxyと元距離の比較、integrated初回はdataclass JSON化で停止した。いずれも新規出力とログを残して修正し、成功したcoverage_attempt03／integrated_attempt02を採用した。旧Dや凍結入力に修正を加えていない。

補足snapshot benchmark初回のNumPy整数JSON化失敗も保持し、成功したSNAPSHOT_BENCHMARK_attempt02のみを比較に用いた。最終コードのテストは55件合格（既存41＋新規14）、実験結果の独立照合は142項目合格である。作業前から存在した4,285ファイルのハッシュを再確認し、変更・消失は0件であった。旧成果の検証台帳102ハッシュも維持した。保全根拠はRUN/PRESERVATION_BEFORE.json、PRESERVATION_AFTER.jsonである。commit・pushは実施していない。

## S1の量子ビットと主問題

S1はN=1000、F=10、B=2、最大20便であり、全20便を使っても平均50地点／便である。これは各便に50地点を固定する条件ではない。q=1に対するQ≥50は同一容量の場合の必要条件であって、容量設定値でも運行可行性の十分条件でもない。

原著型位置表現で候補顧客数n、最大L地点、固定拠点ブロックを除いた量子ビットは(n+1)Lである。50候補・最大50地点でも2,550量子ビット、全1000候補・最大50地点なら50,050量子ビットである。元の固定拠点ブロックを保持すれば、それぞれ51および1001量子ビットをさらに要する。状態ベクトルの生メモリは16×2^q bytesであり、2,550量子ビットでも通常環境では実行できない。

本実装の3候補・2位置は8量子ビット、4KiBの生状態ベクトルである。50地点を固定順の3区間へ縮約し、最大3区間を表すなら(3+1)×3=12量子ビット、生状態64KiBという表現上の削減は可能である。ただし、区間内部順序・反転・分割・車両間再割当の多くが消える。今回検証したのはQ=2の短いマクロだけであり、50地点便を作るマクロ価格付けは未実装である。

S1でJ本の日列を保持したRMPは、顧客1000等式、車両10上限制約、U=ceil(H/Δ)バース上限制約、ε指定時1制約、J変数となる。疎行列nnzは各列の訪問顧客数＋1＋占有slot数＋任意のε係数の総和である。車両数より多い列候補を保持して、その中から最大10本の日列を選ぶ。J、反復数、量子呼出し数は未知であり、今回の値から実測予測しない。時間刻みを半分にするとUは概ね倍になるが、可能な積込開始組合せと列数はそれ以上増え得る。

勤務時間H、Δ、荷物個数容量、準備・積込・地点作業時間、研究ODが未確定なので、S1の具体的なRMPメモリ・深さ・TはHOLDである。全列カタログの巨大化は量子回路を縮小しても解消しない。

## 接続に必要な実装順序

1. **全列カタログ非依存の完成器**：生成便の連結、車両割当、開始時刻生成を遅延実行し、真の日列被約費用を再計算する。小規模で本カタログとの集合・目的値一致を必須とする。
2. **容量が2を超える候補域**：候補区間の分割・結合・境界移動・向き・再配置を更新可能にし、未探索状態を記録する。ペア被覆を一般の完全性と称しない。
3. **整数化に必要な列の生成**：全ゼロ列を列挙する代わりに、1～2車両の置換価格付けを行う。正被約費用列が必要となる人工問題を追加する。
4. **ε別価格付け**：距離・待機双方の制約下で新しい双対snapshotを求め、観測非劣点の欠落を監査する。
5. **V2の追加seed・異なる非一様移動時間**：今回の一様時間・Q=2で得た日列数の式を外し、容量・時間・バースが競合する独立holdoutで検証する。
6. **研究運行・OD条件の採用確認**：凍結需要は保持したまま共通OD・容量・時間規則を確定する。小規模の出力を実大田区結果に読み替えない。
7. 以上を満たした後にS1着手を再判定する。今回S1は実行していない。
