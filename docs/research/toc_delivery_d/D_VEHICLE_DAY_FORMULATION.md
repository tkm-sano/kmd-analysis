# D：時刻付き車両日列モデル

2026-11-11。[外部監査](D_EXTERNAL_CODE_AUDIT.md)完了後に確定した小規模参照の定式化である。HuangのCG＋AOAを維持し、日列・時間・共有バースは独自拡張とする。研究のRQ・仮説・需要・道路・車両条件を変更しない。

## 1. 入力と日列

顧客i∈C、物理車両v∈V、最大便番号b∈{1,2}を使う。d_ikは距離[km]、τ_ikは移動秒、q_iは荷物個数、Q_vは便容量、s_iは配達作業秒、ℓ_vは積込秒、p_vは帰着後準備秒である。今回の検証では全て明示的な人工値とする。研究用のQ・作業/運行時間・ODは採用HOLDのままである。

日列jは車両v(j)、勤務開始/終了、0〜2本のTripScheduleを持つ。各便に順序付き顧客集合、荷量、距離、travel/service秒、積込ready/start/end、出発/帰着、準備、占有slotを持たせる。日列全体にD_j、W1_j/W2_j/W_j、積込作業秒を保持する。0便は空のtrip tupleであり、未使用便に顧客・積込時刻を作らない。主問題では未選択でも未使用を表せる。

便を使用する場合は非空で拠点発着、一度訪問、Σq_i≤Q_vである。同じ日列の2便間でも顧客は互いに素とする。

\[
r_{v1}=r_v^{\rm external},\quad
r_{v2}=a_{v1}+p_v,\quad
L_{vb}\ge r_{vb},\quad E_{vb}=L_{vb}+\ell_v,
\]
\[
departure_{vb}=E_{vb},\qquad
a_{vb}=departure_{vb}+\sum_{(i,k)\in R_{vb}}\tau_{ik}+\sum_{i\in R_{vb}}s_i
\le H_v.
\]

勤務開始≤初便ready、2便目のみの使用不可、準備中はバース非占有とする。途中・出発前の任意待機は導入せず、拠点でready後に待つ時間はWに含む。readyを遅らせてWを小さくしない。

\[
D_j=\sum_{b,(i,k)\in R_{vb}}d_{ik},\quad
W_{bj}=(L_{vb}-r_{vb})/60,\quad W_j=W_{1j}+W_{2j}.
\]

積込作業Σℓ_v/60、帰着後準備、移動、配達作業はWと別に記録する。顧客時間窓は設定しない。

## 2. バース表現と時間精度

時刻原点0と刻みΔ秒を固定し、積込開始をΔの整数倍から選ぶ。占有は半開区間[L,E)である。slot u=[uΔ,(u+1)Δ)と区間が交差するとb_uj=1とする。列内の同一車両の積込区間は重ならないため1slotで二重計上しない。

今回の主fixtureは移動120秒、地点作業120秒、積込120秒、準備120秒、勤務0〜1680秒、初便ready=0、Δ=120秒とする。全値が格子上であり、入力値の丸めはない。ただし全列挙の「厳密」はこの有限格子の範囲であり、任意の連続時刻全域の証明としない。

粗い格子でreadyを次の開始格子へ切り上げる局所差は0以上Δ未満であり、その後の便・競合へ伝播する。全体の誤差を一律Δ未満としない。別の60秒readyの人工例でΔ=60/120の待機差をテストする。一般の非整列区間は交差slotを保守的に占有させ、連続時間に対して可行候補を失う可能性を明示する。

選択後、interval sweepで同時数を独立に再検査し、同一性能Bバースへ終了優先のinterval coloringで具体的berth_idを付す。主問題の占有制約を無視した事後修復ではない。

## 3. 主問題・LP・双対

全格子日列集合J、顧客訪問係数a_ij∈{0,1}、選択θ_jについて

\[
\min\sum_j c_j\theta_j,\quad
\sum_j a_{ij}\theta_j=1,\quad
\sum_{j:v(j)=v}\theta_j\le1,\quad
\sum_j b_{uj}\theta_j\le B.
\]

整数選択はθ∈{0,1}、LPはθ≥0である。各物理車両の行があるため使用台数はF以下であり、別の同値な台数行は重複して追加しない。最大2便・便容量・時間接続・勤務は列の可行領域に組み込む。顧客割当と訪問順の違う列を同時に選択候補へ入れ、先に車両担当を固定しない。

DとWに優先順位を設けず、独立したD最小化とW最小化を検証profileとする。補助上限付きなら、D-profileでΣW_jθ_j≤ε_W、W-profileでΣD_jθ_j≤ε_Dを追加する。無根拠な加重和や距離優先の採用規則を設定しない。Tは目的ではなく計算方法の測定値である。

顧客双対π_iは自由符号、車両双対σ_v≤0、バース双対κ_u≤0、補助上限の双対μ≤0である。補助値g_jを使えば

\[
\bar c_j=c_j-\sum_i\pi_i a_{ij}-\sigma_{v(j)}-\sum_u\kappa_u b_{uj}-\mu g_j.
\]

D-profileではc=D[km]、g=W[min]、μ[km/min]である。W-profileではc=W[min]、g=D[km]、μ[min/km]である。補助上限なしならμ=0とする。双対目的はΣπ+Σσ+BΣκ+εμであり、LP目的と一致することを確認する。LP列に上限1を置かず、車両行で上限を与えるため未計上の個別bound dualを作らない。

## 4. 初期可行性と価格付け

可行初期日列がない場合は、訪問等式へ人工変数e_i≥0を追加したPhase I minΣe_iを別に解く。日列c_j=0として同じ車両・バース・補助上限行を持つ。Phase Iが0になれば人工変数を取り除いて本目的へ移る。巨大な罰金や未配送の黙認を使わない。人工変数が残る解を配送計画として出力しない。

古典oracleは全容量可行な単独便を列挙し、同一車両内で顧客が重ならない順序付き0/1/2便と全許容開始時刻から日列を作る。全日列で最小rcを調べれば有限格子内の厳密価格付けになる。

AOAは**単独便の顧客選択と訪問順**だけを生成する。既存PricingAOAのone-hot/ALiM/XY/COBYLA/測定を変更しない。価格付け用proxyはD-profileで距離−π、W-profileで(−μ)距離−π、Phase Iでは0距離−πを用いる。proxy距離は量子係数を作る一時的な人工入力であり、共通ODを上書きしない。

AOA便と、初期/既存RMP便・単独顧客便を組み合わせ、元の順序を保持して1/2便と全許容積込時刻へ完成する。AOA便を含む日列だけをAOA由来候補とし、候補に含まれる顧客・順序を古典処理で自由に作り替えない。完成後に元距離・全時刻・全双対からrcを再計算する。単独便rcを日列rcに代用しない。

原著AOAへ車両・バース・時刻の全双対を直接埋め込んだものではなく、候補生成＋古典日列化の独自拡張である。AOA未取得ではAOA_NO_IMPROVING_DAY、全格子oracleの非負下界でのみGRID_PRICING_CERTIFIEDとする。

## 5. 整数解・独立検証

限定日列集合の整数最適解と、全格子日列からの整数参照を分ける。2車両の人工問題では顧客maskの補集合と占有maskを用いた独立の全組合せ探索でも参照解を得る。LP閉鎖で全域整数最適を保証せず、整数gapを別に測る。

可行性検査器は元入力から荷量・距離・時間・ready・勤務・占有を再計算し、生成器の保存値を信用しない。全訪問の重複/欠損、同一車両の複数列、バース競合、時間不整合を理由コードで返す。全列参照でも解がない場合のみ、この有限格子・人工条件内の不可行と呼ぶ。
