# 勤務・休憩制約 v1：実装と可行性検証

対象版は `duty-break-20261121-v1`。ユーザー指定の研究条件を別版で実装した。**本実験全体のFreeze・正式実行は行っていない。** 既存正本、共通条件v1.1、FCFS_v1、I_dualによるD最終選択、p/shots、n/K/R、J/検定を変更しない。

Wは第8節の式および現行Freezeに従う**全活動便の総積込待機［分］**。依頼冒頭の「分／運行」とは表記差があるため、無断で運行数による除算はしない。平均Wや積込作業・休憩を主要Wに混ぜない。

## FCFS・休憩伝播とD/W

FCFSの優先キーは `(ready, 車両ID文字列, 便番号)`、共通待機列、利用可能バースのID最小で維持する。途中休憩で第1便の帰着が変われば第2便のreadyを変更し、他車両も含めた全待機列を再計算する。積込終了時には即時出発する。便間・積込中・積込直後への休憩や、12時までの新しい経路待機を入れない。

到着時に休憩する場合、到着時刻を保持し、3600秒の休憩終了後に120秒のサービスを行う。サービス後の休憩も別区間として保存する。走行・サービス・積込・FCFS待機との半開区間重複を独立検証する。CPの帰着式にも3600秒が現れるが、**休憩位置の適格性と全車両FCFSを同じモデルで制約し、実訪問時刻を再構築して照合**する。最終帰着への事後加算ではない。

人工4配送先の時間伝播テストでは、第1便休憩によりv0第2便readyが1時間遅れ、v1第2便との積込順が逆転する。v1のWは29分→0分となる。これは休憩の差引きではなく共通待機列を計算した結果である。

局所更新はD'≤D、W'≤Wかつ一方以上の厳密改善のみ。最終4枝のI_dual規則は変更しない。旧版の4枝回収CLIは新版schemaを受け入れないため、正式全体Qの新版登録・回収接続はHOLD。距離優先への代替・量子エンジンの古典代役への切替は行わない。

## 停車地点と残るHOLD

既存データには道路snap・建物由来・デポ入口の根拠があるが、休憩時の駐停車可否を保証する台帳は確認できなかった。実データで確認済み休憩地点は0件。再生は `--allow-unverified-rest-locations` を明示したモデル仮定で、各休憩に `location_status=assumed_unverified` を記録した。実運行上の可行性を証明したとは扱わない。

場所の根拠がある場合の入力は「既存地点ID→確認根拠」。記録は `caller_confirmed` で、コードによる現地調査や法令確認とは区別する。根拠なしを勝手に昇格しない。既存ODにない休憩施設への迂回は新ノード・OD・経路モデルが必要なので拒否する。現状で迂回を追加して距離を無計上にする経路はない。

本実験前に必要なのは、休憩可能地点の根拠、必要なら承認された迂回表現、新勤務版での正式Q全体・C参照・4枝回収の接続、既存未確定のn/K/R・COBYLA・T・J/統計支持である。今回の共通休憩配置規則は実装上の決定的な研究仮定であり、休憩配置の全探索や最適性の証明ではない。
