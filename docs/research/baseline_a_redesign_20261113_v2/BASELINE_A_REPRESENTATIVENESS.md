# ベースラインAの代表性検証 v2

Aは「区域ごとに仕事を配分し、順序を決め、帰所して再積込する」という業務構成を、共通の研究条件で実行する**未校正の暫定規則モデル**である。特定事業者の配送実績、現行の標準アルゴリズム、人手作業の再現モデルとは呼べない。[証拠台帳](BASELINE_A_EVIDENCE.md)、[仕様](BASELINE_A_SPEC.md)、[校正適格性表](CALIBRATION_ELIGIBILITY.json)を根拠とする。

## 判定

|対象|判定|成立範囲・不足|
|---|---|---|
|業務構成の代表性|CONDITIONAL|担当区域・順序判断・帰所再積込という構成には根拠がある。静的な需要、全配送完了、最大2便、限定バース、時間窓なし等の仮定の下に限る。特定拠点での固定/変動区域、担当者決定過程、夜積み、動的再配達、予約バースは再現していない|
|定量的な代表性|FAIL|同じ対象業務・計測境界でのD/W/Tの適格な校正資料・独立検証資料がない。生成と実行可能性の検査だけでは判定を上げない|
|配送実績を想定するAとしての総合代表性|FAIL|定量代表性を満たさず、具体規則にも事業者採用の証拠がないためである。暫定モデルの存在と、主比較採用条件は別である|

ここでFAILは「どの実配送にも合わない」という実証ではなく、本研究が要求する代表性の採用条件に必要な根拠が不足するという判定である。

## 定量的な校正と外部実績の照合

採用前の適格性条件は、配送のみ/集配の区別、一意地点/荷物の区別、車両・便・拠点の範囲、日数・標本、距離arc範囲、待ちreadyと積込開始、人手/プログラムと全体計画工程が判別できることである。需要・車両数が同じでなくても適用できるモデルはあり得るが、その換算関係をデータから推定・検証できなければ採用しない。

校正係数の推定・恣意的倍率による換算は実施しなかった。数値同士の近さを検定する前に適格性で不採用となったため、外部値に対する誤差率や一致度の値も作らない。適格なデータ0件であり、校正完了・独立検証完了としない。

生成D/V、W/活動便、地点数/車両等は出力の内部記述量として集計できる。ただしD/VとS06の1台実測値を並べても、母集団・業務・区域の一致を証明できない。モデルの平均距離が都心の13kmと異なってもその差を隠さず、対象条件が異なるため外部妥当性の合否を直接導かない。

現実的な作業量について、1車両100地点なら地点作業だけで200分、2便積込60分であり、さらに移動・待ちを加える設定である。これはモデルの算術的含意であり、1台100地点を処理できる実績の証明ではない。建物内徒歩・複数顧客へのまとめ配達・再配達・休憩の扱いによって、実勤務との関係は変わる。静的道路時間も実渋滞の分布を再現しない。実務では駐車後に徒歩で複数の届け先へ向かう場合があり、各地点を車両の道路訪問とする本研究と移動の単位が異なる可能性がある。これはAだけでなく共通入力・評価モデル全体の外部妥当性の課題であり、Aだけ道路距離を割り引いて修正しない。

## AとBの区別

Aは区域政策＋順序仮定＋固定FCFSである。Bは有向Clarke–Wrightの節約量で便候補を生成し、共通古典完成器で車両・便・バースを決める。AはBの探索回数や予算を減らした設定ではなく、生成過程・スケジュール政策が異なる。AはB/C/Dの最終計画を読まず、CP完成器による改善・修復も使わない。

一方、両方とも古典的ヒューリスティックを含むため、「Aは実務、Bは従来計算」という分類の実証的な独立性は未確立である。A対Bの性能差は区域・順序・バース政策が合わさった差であり、単に人間対古典最適化の差とは解釈できない。現代の配送会社がすでに自動ルート生成を使うS02/S03/S04の事実とも両立させる必要がある。

## 公平性と主比較への採用条件

凍結需要、Route OD、車両・便・容量・バース、ready、サービス時間・勤務範囲、D/W定義と共通可行性検査は揃えられる。Aの新Tは二重検証込みprogram Tである。B〜Dは4枝並列を維持し、Aは同じ4コア上限枠内の1コア実行である。実使用資源は同一でないため、資源上限が同じ条件でのプログラム性能差として解釈する必要がある。

旧逐次B〜D結果や、CP完成後の旧AのD/W、T人手値、旧60秒参照を新Aの結果と一緒に主比較しない。現DWTにはAを除外する旧score契約があるため、その変更・参照値固定・ε/予算セルへの適格性判定・統計計画は別途必要である。今回の各2回の動作確認は正式T基準の推定ではない。

研究仮説の実績ベースラインとして主比較に採用するには、適格な運行資料によるD/Wの校正と独立検証、実務方式との対応、必要なら対象工程を揃えた人手計画時間の取得が残る。プログラムTだけを比較することを明示しても、配送実績の代表性の不足を解消したことにはならない。暫定モデルとしての感度・手順検証は可能である。
