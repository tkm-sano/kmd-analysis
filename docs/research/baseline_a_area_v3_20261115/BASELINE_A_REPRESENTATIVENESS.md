# 段階7：代表性と主比較への採否

公開資料のみという条件で、対象/類似実績の探索、資料適格性の照合、訪問順成分の校正・独立検証を実施した。**京浜トラックターミナルを起点とする大田区ToCの実績代表としてはFAIL、研究仮説の主比較への採用は不可である。** 公開資料から取得できなかった項目を、実装成功で補ったとは判断しない。

段階7の調査・判定作業を終了することと、適格な対象実績との照合を達成することは異なる。後者は未達成である。未公開データの提供を求めたり、外部へ連絡したりしていない。

## 代表する対象と実際に計算するもの

代表したい対象は、当該末端拠点の車両別割当、訪問順、帰所再積込、出発積込バース利用、全車両の走行と積込待ちである。現在の実装が生成するものは、合成凍結需要と共通Route版OD・運行仮定の下での、区域割当・最近隣・容量分割・FCFSという再現可能な規則計画である。実事業者の実アルゴリズムや実績そのものではない。

今回、入力座標から小区域を生成する候補を9通り追加し、米国の履歴時間に基づく訪問順だけを校正した。NNが最低損失となり、自動区域候補の採用は支持されなかった。NN維持は比較した10候補の中の選択結果であり、実務の同等性認定ではない。未採択区域候補のS1〜S3出力は動作診断に限定する。

## 二つの代表性判定

|判定対象|判定|根拠と未解決事項|
|---|---|---|
|業務構成の代表性|CONDITIONAL|区域配送、順序判断、帰所再積込という一般構成は公式資料にある。一方、現地の区域変更・具体順序・便上限・出発バース規則は未確認である。角度、境界移動、NN、容量分割、FCFSは明示した研究仮定である|
|定量的な代表性|FAIL|訪問順成分は米国の拠点独立検証を実施したが、区域再進入の差が残る。対象/適格類似拠点の全体D/W/Tと同等性基準は未取得である|
|配送実績を想定するA全体の代表性|FAIL|上記を統合し、主比較で実績を代表すると呼べる根拠に到達していない|

FAILは対象実績が絶対に存在しないという断定ではなく、今回必要な採用根拠を確認できなかったという判定である。

## AとB、比較の公平性

|項目|現在の状態|主比較へ必要な対応|
|---|---|---|
|AとBの区別|Aは区域・最近隣・容量分割・FCFS、Bは有向Clarke–Wright候補と共通完成器である。AをBの弱い探索時間設定として作っていない|この違いは計算方式の区別として説明できる。ただしAの実務代表という役割は別途実証が必要である|
|需要・OD・制約・D/W|同じRoute版入力と共通v1.1を使い、同じ共通検査に加えAはDecimal独立再計算を行う|旧Table/準備900秒/単車両/CP完成器付き旧Aの出力と混ぜない|
|Tの意味|今回のAはprogram wallである。人手Tと混ぜない|全方式で入力から最終二重検証までの工程を明記し、資源を揃えた正式反復計測を別に固定する|
|資源|Aは利用可能4コア枠内で1コア使用。B/C/D通常経路は各方式内4枝、各枝native1である|利用可能枠と実使用の両方を記録する。並列と旧単コアのTを同条件として扱わない|
|評価パイプライン|既存DWTにはAをprogram J/Paretoから除外する旧契約と、人手T/旧参照の経路が残る|今回の新CLI出力を自動的に旧Jへ差し込まない。比較契約の新しい版が必要である|
|研究条件と道路説明|共通設定に旧Table用の説明文字列が残るが、実入力はRoute版でhash固定している|主実験開始前に文書上の不整合を新しい採用版で解消する。今回は値・hashを無断変更しない|

従って、同じ数学的問題に対する暫定アルゴリズム対照としては条件付きで比較できる。一方、**現在のRQの「配送実績を想定するベースライン」として公平な主比較が完了しているとはいえない**。B/C/Dのアルゴリズム変更や再実行でこの不足は解消しない。

## 正規化と主実験

数式上、同じ比較条件に対する正の有限なD_A/W_A/T_refを固定すればA基準のJを定義できる。しかし今回の動作確認2回から正式T_refを確定しない。各結果の `formal_T_reference=null`、`J=null` を維持した。Jが計算できることと実績代表性の成立も別である。人手TをプログラムTへ換算して分母に置かない。

公開資料限定を維持したまま主比較を認めるには、少なくとも次の不足を解消する必要がある。

1. 対象、または適用可能性を説明できる国内類似ToC拠点の需要規模・車両割当・便・実距離・積込イベントを対応づけられる公開実績を取得する。GPSのみではWのreadyが定義できない。
2. 実区域・順序・便・バース運用と研究仮定の対応を確認する。角度/中央値区域の妥当性が立証されない場合は、候補の追加設計と新しい未使用検証集合が必要である。
3. 校正用と最終検証用を拠点/日単位で分け、業務上の根拠ある許容誤差を検証前に定め、D/Wと補助指標の適合を評価する。任意の割合で合格させない。
4. T_programを主とする比較の意味を明示し、共通の資源・工程・反復数・代表値・失敗扱いを事前固定した新評価版へ接続する。人手時間の代表を議論するなら別の適格な工程記録が必要である。
5. 道路/入口/スナップ等の残る現実対応、評価契約と正規化基準を確認してから本実験へ進む。

公開資料だけでは不足が解消しない場合、現在のRQ・仮説を保ったまま実績代表としての主比較を開始しない。仮定に基づく規則対照として補助実験に使うことは可能であるが、その役割へ研究設計を変更する判断は別途必要であり、今回自動変更していない。
