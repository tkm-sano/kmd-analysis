# 校正と拠点独立検証

今回の目的は、前回観測した最近隣法の区域再進入の差を、入力座標から作れる区域優先規則で改善できるかを検証することである。前回の結果を見た後の開発であり、今回の保留拠点だけを新しい検証集合とする。[事前固定手順](PROTOCOL.md)と[設定](../../../configs/toc_delivery/a_area_v3.json)に基づく。

## データと分離

Amazonの2018年米国配送実績を使用した。原本は[公式公開データ](https://registry.opendata.aws/amazon-last-mile-challenges/)であり、[データ構造](https://github.com/MIT-CAVE/rc-cli/blob/main/templates/data_structures.md)と[公式scorer](https://github.com/MIT-CAVE/rc-cli/blob/main/scoring/score.py)を確認した前回の原本・hashを再利用した。非商用ライセンス等の条件は[前回保存原本](../baseline_a_sequence_validation_20261114_v1/sources/LICENSE.txt)による。追加の有料計算・データ購入は行っていない。

公式説明のevaluation3072件に対し、取得したmetadataとactualの実件数は3052件である。理由は未確認であり、3072件取得したと報告しない。既存cacheの6ファイル890,019,237bytesをすべてhash確認した。無駄な再取得は行っていない。

|集合|拠点|ルート数|役割|
|---|---|---:|---|
|校正|DBO1, DBO2, DBO3, DLA9, DSE2, DSE5|32|NNと9区域候補を比較し、パラメータを固定する|
|独立検証|DAU1, DCH1, DCH3, DCH4, DLA5, DSE4|26|選択後に一度採点する。候補や重みを変更しない|

各集合最大6拠点×3日×2ルート=36という上限をメタデータhash順に適用した。日ごとの公開件数不足は再抽選で埋めていない。前回30ルートおよびpilot2ルートを使用した全拠点日を除外し、検証は前回pilotを含む既使用拠点からも分離した。校正と検証の拠点集合の共通部分は空である。全ルートID、除外拠点日、入力hashは[SPLIT](../../../output/toc_delivery/a_area_v3_20261115_study01/SPLIT.json)と[INPUT_MANIFEST](../../../output/toc_delivery/a_area_v3_20261115_study01/INPUT_MANIFEST.json)に記録した。

公開competition evaluationファイルを研究内で再分割しているため、競技公式のtrain/test構成を維持した評価ではない。都市内拠点間の相関や地域差は残り、日本への外的妥当性を保証しない。担当先が与えられた条件での訪問順成分の検証であり、本体Aの割当を既存ルートリスト読込へ置き換えたものではない。

区間は6拠点を単位とする5000回再標本化であり、route等重みの表の単純な差とは一致しない場合がある。6クラスタの小標本で、多重な診断比較もあり、広い母集団や日本の運用について確証的推論をしない。

公開zoneを入力する診断は、評価にも使う区域ラベルを追加情報として与えるため、再進入指標に構造上の有利さがある。実績順を入力してはいないが、本体自動区域モデルと同じ情報条件ではない。score・行列時間にも改善はあるものの、実務との同等性や大田区の区域定義が確認されたわけではない。

移動時間比は実績順と生成順を**同一の履歴平均時間行列**で閉路評価した比である。当日の実運行経過時間、総走行距離km、積込待ち、計画作成時間ではない。公開zone欠損は既知zone部分列で扱い、全域の再進入を完全観測したと主張しない。

## 採用判断

自動区域規則への置換は支持されず、区域候補の正式採用は見送る。NNを研究内の選択結果として保つが、これはNNが実務を十分代表するという合格ではない。NNでも再進入22.692に対し実績0.5という差が残る。根拠ある同等性許容幅は未取得でありnullである。

道路距離行列はAmazon schemaにないため、時間による校正を大田区の道路距離規則に移す検証は未完了である。座標距離診断を道路距離検証と呼ばない。割当・容量分割・複数便・FCFS・全車両D/Wは今回の外部検証の範囲外である。全体の実績代表性をPASSへ更新しない。

正本は[SUMMARY](../../../output/toc_delivery/a_area_v3_20261115_study01/SUMMARY.json)、[全採点CSV](../../../output/toc_delivery/a_area_v3_20261115_study01/ALL_METRICS.csv)、判断trace、全順序、分割、入力manifestである。解析19.13秒は分析処理時間であり、A_program比較値へ転用しない。

同じ入力・設定を別出力へ再実行したところ、分割、選択モデル、校正/検証の全提案順序と全採点値、trace、全CSV、集計、入力manifestの10種がバイト一致した。[再現記録](REPRODUCIBILITY.json)を保存した。同じ32/26ルートの再現確認であり、独立実績数を倍にしていない。
