# B〜DのCPU並列実行（2026-11-13）

ユーザー指定「B〜DはCPUで並列化、今後も同様」に対応する実行方式。通常の入口は `scripts/run_dwt.py` と `scripts/run_dwt_bundle.py`、既定設定は [dwt_balance_v1_4_cpu_parallel.json](../../configs/toc_delivery/dwt_balance_v1_4_cpu_parallel.json)。旧設定・旧結果は履歴として保持する。

## 実装した方式

| 対象 | 並列単位 | 既定資源 | 候補の扱い |
|---|---|---|---|
| B：有向Clarke–Wright＋共通完成器 | 手法全体の内部マルチスタート | 4プロセス、各1コア・native 1 thread | 独立検査を通った枝を比較 |
| C：OR-Tools＋共通完成器 | 同上 | 同上 | 同上 |
| D：限定AOA＋車両日列＋共通完成器 | 同上 | 同上 | 同上、未選択枝を含む量子処理量も保存 |
| D量子なし対照 | 同上 | 同上 | Dと同じCPU枠 |

各枝で車両割当・訪問順・共通完成器・共通検査・第二再計算まで既存手法を実行する。ルート計算の各ループを4分割する方式ではない。B/C/Dを同時に走らせて時間を測る方式でもない。OR-ToolsのRouting自体を4スレッド化したとは主張しない。

外側の一試行の中で4つの内部候補を生成し、全制約・W上限・枝の予算を満たす候補からD最小、次にW最小、最後に枝番号の順で一つを選ぶ。D比較は既存完成器と同じ0.1m整数精度を使う。選択前に各候補を共通検査・独立再計算で照合し、選択後にも二重検証する。外側のε制約や目的関数を新しく決めたものではない。

既存探索の数学的処理を保ち、実行管理・seed派生・CPU上限・候補選択を追加した。このため、同じ外側seedでも旧逐次版の探索列やD/W/Tを再現するとは限らない。決定論的な生成器は複数枝で同一候補を返し得る。4倍高速化や改善を保証せず、B〜Dの新しい性能分布は並列条件で改めて測る。

## CPUと停止条件

既定では許可されたaffinity内から異なる物理コアを自動選択し、各枝を1論理CPUへ固定する。親も同じ4CPU枠内で選択・検証を行う。CPU不足はエラーとし、逐次処理へ黙って切り替えない。明示CPU指定は使用可能・重複なしを検査する。SMTの扱いは実行環境とともに記録する。

OMP/OpenBLAS/MKL/NumExpr、CP-SAT、HiGHSを枝あたり1threadへ制限する。HiGHSはSciPyのoptions経由で `threads=1` を明示する。SciPy 1.16では「未認識optionsをHiGHSへ転送」の警告を出すが、オプション転送経路と小規模LP/IP実行を確認した。既存呼出しでnative_threads未指定なら旧挙動を維持する。

親のτの80%を全枝の共通絶対締切とし、残り20%を回収・選択・最終検証に予約する。枝には実際の残時間を渡し、その中で既存の工程配分を使う。予約だけで予算遵守を保証せず、最終実測T>τは失敗とする。締切で生存枝を停止・joinし、利用可能候補だけを検査する。全枝失敗時は診断のみ保存し、架空の計画を生成しない。

## T・資源・量子処理の記録

`T_program` は親の共通入力読込直前から、全枝停止確認・候補選択・採用計画の二重検証完了までのwall time。枝の時間の平均・最大だけをTへ代入しない。

全手法共通のライブラリ読み込みと待機プロセス起動は、配送入力・ソルバー・量子回路を実行する前に別計測する。cold startを含む利用者経過時間は、この準備時間・T・出力時間を併記して評価する。GeoJSON/CSV/描画はT外。

全枝のPID、CPU affinity、seed、状態、失敗理由、D/W、wall/CPU時間、RSS、回路数、訓練/最終shotsを記録する。未選択枝の資源を除外しない。強制終了等で計測が欠ける場合は完全なCPU/量子総量をnullとし、観測済み部分と区別する。RSS合計は共有ページを重複計上する各プロセスhigh-water markの合計上界であり、同時物理メモリの実測ピークではない。

## 乱数と統計単位

外側のsolver_seed・quantum_seedと固定ドメイン識別子から `SeedSequence.spawn` で枝系列を作り、各枝でさらにsolver/quantumを分離する。全派生seedを保存する。枝内の既存AOA訓練・最終測定の乱数運用は変更しない。

**4内部枝＝1外側試行**。独立需要事例数n、アルゴリズム反復r、shotsへ内部枝数を足さない。外側の需要・反復・予算条件は別途事前登録する。既存の単コアT・分散・試行数見積りは並列実験へそのまま流用しない。

## 起動と再現

リポジトリrootで、既存検証環境のPythonを使用する。

```bash
PYTHONPATH=src PYTHONDONTWRITEBYTECODE=1 \
  /home/takuma/.cache/kmd-analysis/venvs/ad-pipeline-v1/bin/python -B \
  scripts/run_dwt.py --help
```

`run_dwt.py register/run` は既定で並列設定を使う。既存の逐次登録を新既定設定に渡しても、実際の登録内容を検査して拒否する。過去逐次結果の再現だけは `--historical-serial-reproduction` を明示する。APIには旧テスト・履歴再現の互換経路を残すが、通常の新規B〜D実験には使わない。

`run_dwt_bundle.py` は既定で小規模の登録・実行に限定し、限定S1系列は明示的な `--include-limited` が必要。本作業ではこれらの道路予備/限定/本実験コマンドを実行していない。実験開始の許可・統計的準備と実装完了は別である。

CPU数を変えるときは新しい設定版で `threads` と `cpu_parallel.workers` を同じ2以上の整数へ変更し、全手法に共通適用する。既定cpu_ids=nullなら再解決する。出力rootも新設し、旧結果を上書きしない。

Linuxのimport-onlyかつnative thread=1の親からforkする経路を実動作確認した。条件を満たさない場合のspawn経路も実装したが、今回の実プロセス検証はfork経路のみであり、他OS・spawnの実測保証はない。
