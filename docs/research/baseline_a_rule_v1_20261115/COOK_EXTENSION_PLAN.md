# Cook順序成分の接続契約

今回実装済みはNN版の交換interface `orderer(nodes, problem, context=None) -> tuple[node_index,...]`、その完全置換の検査、順序生成後の容量分割、全体時刻への接続、呼出回数/呼出wallの記録である。Cookアダプタそのものは未実装。Cook接続はA_rule_v1完成の条件ではない。

入力nodesは現在の一車両の未順序の割当集合、0は拠点。ODは同じ有向費用、IDは元IDを同定する。出力は拠点を含まないnodesの一回ずつの置換。拠点発着を付けるのは後段。便所属を先に固定しない。初期割当の全非空車両で呼び、境界候補では変更した二車両の全割当で再実行する。未変更車両を再使用するかどうかは版で固定する。キャッシュ有無の全体計算一致も検証する。

NN版はcontextを使わず道路距離で最小次点を決める。Cook案のcontextは少なくとも、author commit/ビルドhash、モデルhash、モデルの学習期間・対象・データhash、区域ラベル/階層/未知区域処理、費用定義・整数化、solver seed、path/precedence各予算、外側残時間、学習・推論方針を持つ。実績順序を推論入力へ渡さない。町丁目はAmazon実区域と同等ではなく、階層符号化は研究仮定として別版で定義する。区域なしでも実績代表性は保証されない。

大田区の実区域・対象拠点の順序履歴は未取得。公開Amazon学習モデルを移転する場合の未知区域・station対応、距離費用と履歴時間費用の違いは未検証。学習済みclusterKeys等を含むモデルのどの情報を使うか、時系列漏洩、ライセンスと実行依存関係を実行前に固定する。未入力を推測して補わない。

Cookの全呼出し、未採用候補の計算、アダプタ前処理、必要な需要別準備・学習を外側T_planning/T_programへ含める。共通のオフラインモデル作成を外へ置くなら原本・hash・時間・適用対象を別記する。呼出しが失敗・時間切れなら候補棄却/全試行失敗の扱いを事前登録し、NNへの黙ったfallbackはしない。初回計画も作れない場合は採用D/W/T=null。反復上限V、全体資源上限を守り、呼出数×予算を無制限に増やさない。

保全した著者commitは `dc4ebc0aa091d4d1eb7dc7d9b9b2d8f8c19664ce`。既存AUTHOR_BRANCH.json、BUILD.json、a_cook_transfer_v1.json、著者原本tar、CLI、全失敗/修正ログを照合した。既存試験は1コア、各定式化CPU2秒/wall15秒、seed1、pathとprecedence/transitive、著者1%merge。論文改良版や競技16並列・動的時間配分の全性能再現ではない。過去公式score、逆転率、有向辺一致、区域再進入、閉路時間比と完全逆順診断は変更しない。

追加比較の条件は、専用版・入力条件・予算・seed・失敗方針・独立保留データを先に固定し、小規模のinterface/物理検証を通すことである。車両割当・最大2便・再積込・有限バースは本研究の追加モデルであり、複合方式全体がCook論文で実証されたとは記さない。Amazon scoreの改善だけで主Aへ昇格させない。今回Cookを再実行せず、A_rule_v1をNN版として独立に採否判定する。
