# 限定実行・将来比較の契約

これは正式統計比較ではない。AだけをS1、S2、S3各1回、さらにS2同条件1回の順で逐次実行する。別設定でS2・20台の2バース/8バースを各1回生成段階から実行し、4バースは主設定S2初回を参照する。最大6試行。詳細数値上限・停止・失敗扱いは[確定仕様](BASELINE_A_RULE_SPEC.md)と新版JSONを正本とする。結果による設定選び直しはしない。

S2のバース感度では、まず元の凍結4バース入力を全検証し、その後に新規 `BerthSensitivityProblem` で物理バース数だけを2/8へ置換する。共通Problemの元の凍結需要・件数チェックは4バース参照にも実行し、実バースのレコードと時刻・非重複・同時数は変更後バースに対して共通/独立検証する。共通コードや需要、元のproblem hashを上書きしない。派生problem hashと元canonical hashを識別する。同一物理条件のA〜D比較を行う際は同じ派生入力を全手法へ渡す必要がある。この作業でB/C/Dは実行しない。

共通v1.1の物理条件、凍結需要、拠点、登録Route OD、整数秒丸め、D/W、入力hash、独立検証を共通境界にする。ロード後の道路定義はRoute manifestを正本とする新版参照関係に従う。旧Table OD・旧900秒準備・上流PEは混ぜない。

Aはready順FCFSを固定する。一方、現行B/C/Dの共通CP-SAT完成器は、供給された便ルート集合内で車両・便の割当、候補ルートの選択、積込開始を最適化する。訪問順の内部arcを完成器が書き換えることはないが、車両所属と便所属は変更し得る。積込はFCFS固定ではない。したがって現行契約でのW差には便構成・帰着だけでなく積込順/開始最適化も含まれる。全手法FCFS比較にするなら別の実験設計と実装確認が必要であり、今回変更しない。

AはO/Hを限定改善するため「最適化を一切しない」と記さない。Aは角度初期区域・境界端点・最大V採用・(O,H)先着改善、Bは有向Clarke–Wright候補、CはOR-Tools、Dは量子古典処理と候補生成、B/C/Dは完成器とε制約を含む。目的、探索範囲、区域の使い方、積込決定の違いとして解釈する。

Aは4物理コア枠を確保した上で1プロセス・1コア・native1threadを使う。同じ計画を4回作らない。B/C/Dの通常契約は各4枝×1コア/native1thread、全枝停止・選択・最終二重検証までの親wallを正本とする。今回のAとの資源使用差を開示し、旧単コア結果と同条件と見なさない。各試行のaffinity、PID、RSS、環境、setup/export、入力とソースsnapshotを保存する。同時に別配送手法を起動しない。共有ホスト上の無関係プロセス/OS cacheは制御していないため今回Tは記述値である。

各行はmethod/method_version/scale/scenario_id/demand_seed/solver_seed/repeat_id/run_id/input_hash/config_hash/code_version/resource_contract/status/D/W/W_first/W_reload/T_program/T_input/T_planning/T_validation/T_attemptを持つ。seedを発明せず、凍結原本に数値seedがない場合はnullとしmanifest・抽出rank契約で同定する。solver_seed=nullは決定論的で乱数不使用を意味する。需要シナリオと同じ需要への計算再実行を分離する。

将来は同一シナリオをA〜Dで共有する。S1⊂S2⊂S3を独立標本3件と数えない。再実行・並列枝・shotsを独立需要へ加えない。正式な需要数・反復数・精度目標・T_A_refは別の実験計画で決める。成功試行だけの時間集計をしない。

J候補は `(D_m/D_A+W_m/W_A+T_m/T_A_ref)/3`。同じ需要・規模・時間種別・資源契約の正の有限参照だけを使い、0/欠測/非有限の分母では未定義とする。微小値を足さない。等重みは研究設定、Jの小ささは三指標全ての改善を意味しない。今回はJと正式T_A_refをnullに保つ。旧DWTのT=60秒基準とA除外契約は未改修であり、正式比較への接続は未完了。
