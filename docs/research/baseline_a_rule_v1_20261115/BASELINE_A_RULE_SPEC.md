# A_rule_v1 確定仕様（2026-11-15）

図表名は「A：業務構造を参考にした規則型代理ベースライン」。区域別配送・帰所再積込という公開業務構成を参考に、担当範囲、訪問順、便構成、積込順を研究規則で生成する。対象事業者の配車アルゴリズムや観測一日実績の再現ではない。版は `A_rule_v1-20261115`。数値の優劣は採用条件にしない。

## 入力と共通条件

完成済み車両別リストは入力しない。凍結需要・単一拠点・有向Route ODと共通v1.1の運行条件を読む。新版設定の `conditions_reference` によって、物理条件は共通v1.1、道路定義は登録したRoute manifestを正本とする。旧 `same_table_response` 文言だけを参照契約で解消し、原本と旧入力hashは変更しない。manifest hashと全ODファイルhashを計時内に確認する。

1地点1配送単位、容量60、最大2便、配達120秒/地点、積込1800秒/非空便、追加準備0秒、08:00〜20:00。車両は利用可能台数であり全台稼働の義務はない（共通 `unused_vehicles_allowed=true`）。初便readyは `28800+(3600*(2*v+1))//(2*V)`。非稼働車両は最終帰着null、L=0、Oへの寄与0。空便を生成しない。

## 生成工程

1. 車両indexは共通入力のtuple順。地点IDはNFC正規化し同一化衝突を拒否する。費用・訪問記録は元IDのまま。
2. 原座標EPSG:4326から `x=(lon-lon0)*cos(lat0), y=lat-lat0`。東を0度、反時計回りの `atan2(y,x)%360`、同角度は半径二乗、正規化ID順。拠点同座標はatan2(0,0)=0。開始角は0度のみ。
3. 角度順の `order[N*v//V:N*(v+1)//V]` を初期区域とする。旧A2のproxy負荷調整は呼ばない。
4. 各割当全体を拠点から有向道路距離NNで順序化する。同距離は正規化ID昇順。全順序を生成した後に先頭から60ずつ分割する。空区域に順序器・便・積込を発生させない。
5. 各非空便は拠点発着。各arc移動秒をceilし、到着直後から120秒配達。積込終了時に出発する。第2便readyは第1便帰着時刻。
6. 全車両のreadyイベントを `(ready, vehicle_index, trip_index)` 順に処理する。最小 `(空き時刻, berth_id)` のバースへ割り付ける。積込区間は半開。バースIDは入力の文字列昇順で固定する。

## 境界調整

これは「割当・訪問順・便構成の反復的な共同決定」であり、一体数理モデルの同時最適化ではない。各走査で円環境界 `i,(i+1)%V` をi昇順に列挙し、左の末尾を右の先頭へ移す候補、その逆（右の先頭を左の末尾へ）の順に調べる。V=1では候補なし。V=2では二つの円環境界を保持し、区域の両端を扱う。

V−1と0の境界も同じ規則。移動後の区域は円環上の列として保持し、角度0で再ソートしない。これにより0をまたぐ区域でも次の端点が正しくなる。空区域も車両indexと隣接関係を保持し、飛び越さない。空区域への端点移動は可能、空区域からの移動はなし。任意地点移動、2-opt、複数開始角、多開始点はない。

容量120地点/車両を超える候補を棄却する。両端の割当からNN全順序・便分割を作り直す。変更のない車両の経路形状・所要時間だけを保持し、**全車両のFCFS・帰着を常にゼロから再計算**する。不変tupleを用い、棄却候補で採用状態を変更しない。

`L_v=最終帰着−初便ready`、`O=Σmax(0,最終帰着−72000)`、`H=ΣL_v²`。整数秒・整数二乗和の `(O,H)` を厳密辞書式比較し、最初の厳密改善を採用して走査をやり直す。同値は棄却。D、W、Jは隠れた採用基準にしない。Hは分散ではなく拘束時間の大きさと偏りの双方に反応する。

全地点一回・非空便・容量・便数は初期分割、順序器の置換検査、端点単独移動で保つ。最終共通・独立検証で全制約を再確認する。構築中はO>0を許すが、最終採用にはO=0と勤務・バース制約が必要。

## 停止と失敗

採用移動最大V回、改善なしで `NO_IMPROVEMENT`、V回で `MOVE_LIMIT`。走査数、候補数（容量棄却を含む）、採用数、全候補の前後(O,H)、停止理由を保存する。既定安全上限は入力開始から計画150秒、全体180秒、外側プロセス300秒、仮想アドレス空間4096MiB、候補10000。設定・ソースhashとともに実行前manifestへ保存する。メモリ上限はRLIMIT_ASで強制、全体はSIGALRM、外側はsubprocess timeoutで強制する。

計画の150秒は候補走査の境界で検知し、入力開始から180秒はSIGALRMで強制する。計画上限時、保持計画を共通・独立検証して成立なら `VALIDATED_LIMIT`、通常終了は `VALIDATED`。Oは単調非増加なので、一度O=0になれば後続採用候補もO=0となる。勤務終了超過が残れば `NO_FEASIBLE_PLAN_LIMIT` または `NO_FEASIBLE_PLAN`。それ以外の検証不一致は `REJECTED_PLAN`。これは問題自体の実行不能の証明ではない。入力不正は `INPUT_INVALID`、全体時間切れは `TIME_LIMIT_NO_VALIDATED_PLAN`、外側強制停止は `PROCESS_TIMEOUT`、その他はERROR/PROCESS_FAILURE。検証が完了しなかった場合は採用値を出さない。

成功計画なしではD/W/T_programはnull、T_attemptと段階・原因・棄却計画を保存する。安全上限を延長して改善を試さない。入力容量不足の例外も生成失敗であり実行不能証明とは呼ばない。

## 指標と計時

Dは全非空便の拠点往復を含む道路距離総和/1000。WはΣ(load_start−ready)/60、W_firstとW_reloadへ分ける。積込作業をWへ含めず、負待機を補正しない。バース別積込区間、全便ready/load_start/load_end/departure/return、車両別L・最終帰着・超過を保存する。

T_programはconfig/input読込・hash確認・前処理から、全候補評価、共通検証、独立Decimal再計算、一致判定までのwall。T_input、T_planning、T_validationを連続区間として記録し、T_attemptは失敗を含む実際の経過時間とする。一般ライブラリimport・プロセス準備と出力は別計測。需要別学習はない。OSページキャッシュは非制御、coldを主張しない。独立検証器は生成器・schedule・compile_groupをimportしない。物理的検算は既存Decimal独立検証、FCFSは独立のリストイベント処理、時刻は整数厳密一致、距離許容は1e-7 km（便内1e-6 m）と事前固定する。
