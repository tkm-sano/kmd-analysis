# 数値設定・規則の根拠台帳

確認日：2026-11-16。対象は凍結A_rule_v1と現行A〜D比較契約である。**設定を採択した記録、数値を選択した当初の理由、現在のモデル上の役割、実績の裏付けを別々に扱う。** 役割の説明は本調査でのモデルの読解であり、当初の意思決定を回復したという意味ではない。全行の出典番号は[出典一覧](SOURCES.md)に対応する。

区分は、A＝対象業務の直接的実証根拠、B＝対象と異なる外部参考、C＝研究目的に基づくモデル設定、D＝計算・実装上の設定、E＝採用理由未確認である。C/DとEの併記は、「研究設定であることとその役割は確認できるが、この具体値を選んだ理由は未確認」を意味する。Eの項目では**設定理由は現存資料から確認できなかった**。Aに該当する所在地の確認を、運行値の実証へ拡張しない。

## 履歴監査の限界と差分

1. 現行共通設定・新Aの大半は未追跡であり、ファイル導入commitは取得できない。[Git監査](GIT_HISTORY_AUDIT.json)の空履歴を「履歴を調べていない」ことと混同せず、逆に日付ラベルをcommitと捏造しない。
2. 旧102秒の記載が10/09の追跡文書にあることは確認できたが、値の最初の生成や実測出典は未確認である。旧216PE・旧07:00・旧1200秒・旧900秒準備は現行条件へ流用しない。
3. 共通JSONの旧Table文言と旧A名称は残る。現行は新版の参照契約でRoute版とA_rule_v1を指定しており、原本を無言で修正して整合させてはいない。
4. 旧A2の地点proxy、A-area-v3の外部校正候補、Cook外部試験、新AのO/Hは別の版・構成である。過去のFAIL等の判定も削除していない。対象実績資料の不足は、観測した不適合ではなく未検証と記す。
5. 原指示は全件を回収できていない。設定のauthorityや「明示指示により採用」という既存文書は、採択を記録した証拠である。値の選択理由や外部根拠が全て回復したことを意味しない。
