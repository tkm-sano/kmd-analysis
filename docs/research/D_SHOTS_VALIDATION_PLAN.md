# D shots数の統計的検証・採用計画

2026-11-13。[監査9](D_SHOTS_AUDIT.md)に基づく**未実行の計画**。既存の訓練1,000/最終4,096は変更しない。本実験の最終shotsは未確定。8,192は診断の基準候補であり、統計的に妥当と確定した値ではない。

## 最初の判定：改善可能な候補が存在するか

現在のS1は固定した17便×3fragmentの並べ替え102経路のうち、元便17本のみが距離最小で、残り85本はすべて長い。この領域のままで「shotsを増やしてDを改善する」本実験は実施しない。shots数を選ぶ前に、主要な改善事象が空か、未観測なだけかを分ける。

- **空であると確認済み**：このS1有限マクロの元便より短い完全経路。最終測定を増やしても生まれない。
- **未観測**：確率質量はあるが標本に現れなかった候補。局所回路の正確な分布や二項区間で評価できる。
- **領域外**：別の車両への顧客移動、fragment内部の順序変更、別の時間パターン。shotsの変更とは別のモデル変更である。

局所の被覆・時間を調べる診断は実施可能だが、性能改善実験は、既存の小規模人工問題等で**追加価値のある候補が存在する正の対照**を先に確認してから設計する。新しい探索域を導入する場合は別版・別登録とし、旧S1結果を上書きしない。今回、その実装修正は行っていない。

## 系列F：固定角度の最終測定のみの診断

対象は`S1_FROZEN_PARAMETER_BANK.json`の34個の12-qubit局所回路。訓練済み角度、距離・双対・fragment・p=2・デポ・ペナルティをhash固定する。訓練の再実行・角度調整・候補領域変更を行わず、`Statevector.sample_counts(N)`のNと測定seedだけを変更する。保存角度は既存実験後の診断対象であり、未知問題での性能を検証する事前登録済み学習条件とは呼ばない。

|条件|最終shots/局所回路|初期の独立反復数|目的|
|---|---:|---:|---|
|Q1|1,024|30|低予算での被覆・重複・標本誤差|
|Q2|4,096|30|現行値の基準|
|Q3|8,192|30|優先診断候補|
|Q4|10,000|30|任意の丸い数を選ぶ利益があるか|
|Q5|16,384|30|低確率候補・飽和診断|
|Q6|32,768|30|高shots側の診断。採用を前提にしない|

1反復は34回路それぞれの測定結果をまとめた1候補プールとする。34個の局所回路を独立した配送問題34試行とは数えない。各条件30反復の候補プールを作るので6120回のサンプリング、最終標本総数は`34×30×ΣN = 73,913,280`。訓練shotsはこの系列では0追加。全条件を一度に実行できるかは、別の短い測定時間パイロットと承認された計算予算で判断する。今回これらの測定は行っていない。

`PILOT_SEEDS.csv`に6120個の最終測定seedを予定値として固定した。生成スクリプトは標本を取得せずseed一覧だけを作る。結果に応じてseedを変更せず、失敗・エラーも同じIDで残す。

### 乱数と対応関係

NumPy2.3.1で利用可能な`SeedSequence`を使い、固定root entropyと`(系列, 条件, 反復, kernel, 用途)`のspawn keyから子系列を作る。128-bit生成seedを16進文字列として保存し、JSON/CSVで64-bitを超える整数が丸められることを避ける。Qiskitへ渡す際はPython整数へ変換する。

- 凍結需要はSHA256順位による決定論的選択で、今回の需要生成乱数は**該当なし**。共通入力の`random_seed=20261112`を実際の凍結需要生成seedだと読み替えない。需要manifest/hashとinstance_idを保存する。
- 系列Fのsolver_seedは保存角度の来歴として保持し、反復の測定乱数へ流用しない。
- quantum_seedは条件・反復・kernelごとに別の子系列。1024個の測定のprefixを8192の同じ標本から切り出す設計にはしない。
- validation_seedは確率的検証をしないため該当なし。厳密確率・制約検証は決定論的に行う。
- 同じinstance/kernel/角度は比較のブロックとして共有するが、shots条件間の測定乱数は独立。条件間の標本が同じseed由来なら、独立反復とは扱わない。
- 同seedの一致確認はデバッグ専用。実装の再現性と性能分布の評価を分ける。

### 取得する量子・候補指標

各測定のbitstring→頻度を保存し、次を別の分母で報告する。

1. one-hot符号として有効なshots/全shots、ビット列種類数。
2. 局所復号VALID shots/全shots、部分候補・空・重複・容量超過の内訳。
3. 完全マクロshots/全shots、重複除去完全マクロ数、既知古典経路を除いた新規数。
4. 古典対照に対する真の追加価値がある候補shots/全shots。単なる顧客双対の負RCをこの列へ代入しない。
5. 領域内最良候補を1回以上得る確率。最良とは、固定した目的・制約下の全列参照で定義し、測定後に目標を変更しない。
6. 候補ごとの出現頻度、未取得数、102候補に対する被覆。候補被覆70/102を二項の70成功/102shotsと扱わない。

候補数差は独立な条件間の平均/分布の差として集計する。Q3とQ4の標本を足し合わせて「新規増分」としない。入れ子の候補被覆曲線を補助計算するなら、共通乱数を使う別系列として区別する。

## 系列P：候補を配送計画へ戻す検証

系列Fの固定角度と候補プールを使い、初期CW、古典対照、日列構築、完成器、ε条件、時間上限を固定する。**系列Fのサンプリング時間だけをT_programと呼ばない**。系列Pで共通入力読込から定義した最終検査終了までを改めて測る。S1を含む配送最適化の実行は今回の許可範囲外であり、この計画のみを保存する。

同じ入力・ε・基底計画について、少なくとも以下を保存する。

|段階|保存内容|
|---|---|
|古典基底|CW経路、共通完成器の出力、基底LP/IP、D/W/T、可行性|
|量子提案|回路/角度/seed/counts、部分候補、完全マクロ、既存/新規ID|
|日列への写像|入力マクロID、車両・便・積込時刻、真の可行性、凍結dualでのRC、拒否理由|
|古典補充|負RC・ゼロRC・正RC/整数gap対応の追加IDと件数、出所、時間|
|完成器後|選択経路・日列ID、量子由来新規候補の選択数、D/W、制約違反、処理時間|
|対応古典対照|同じ領域・追加計算予算での古典提案＋同じ完成器。全6順列/元便の参照も可能なら別に用意|

現行`meta.base`は量子を入れない対照として使えるが、既存時間を独立な同予算反復へ代用しない。102経路の全列参照は監査用oracleであり、量子提案へ注入しない。古典全順列を比較手法として実行するなら、その計算・候補日列・整数選択時間も同じTに含める。

### 主要な追加価値の定義

局所候補段階では、古典プールに未登録で、日列へ合法に写像でき、同じ凍結master双対に対して`RC < -1e-7`の候補を主要取得事象とする。RCの単位はD目的ならkm、W目的なら分であり、kmからW双対を直接引かない。整数改善はゼロ/正RC列の組合せでも起こり得るので、この事象だけで最終価値を判定しない。

全計画段階では、古典対照から主目的が改善し、同じε・制約を満たす計画を主要評価とする。主目的同値の副目的改善は別列へ記録する。数値判定は少なくともコードの1e-7許容差を超え、Wは秒単位で整合させる。現場で有意な改善量を追加設定する場合は、結果を見ずに別の閾値として登録する。

現在のS1領域ではD短縮事象が空であるため、任意のNで「D改善を95%の確率で取得する」採用基準は満たせない。**検出力不足と構造的に事象が存在しない状態を混同しない。**

## 統計的評価と反復数

固定回路の固定事象なら二項95% exact区間を用いる。pの区間[L,U]から、単調変換で取得確率区間`[1−(1−L)^N,1−(1−U)^N]`を計算できる。34回路で分布が違う場合は回路別の確率を使う。複数回路を合わせた少なくとも1回取得の事象には`1−Πc(1−pc)^Nc`を用いる。

|shots N|少なくとも1回の取得確率95%に必要な1shot確率p|p=0.0001の場合の取得確率|
|---:|---:|---:|
|8,192|0.000365623|55.9234%|
|10,000|0.000299528|63.2139%|
|16,384|0.000182828|80.5725%|
|32,768|0.000091418|96.2257%|

この表は仮定したpでの計算で、現在の有用日列の測定値ではない。0観測の区間上端は正であるため、観測だけではp=0を主張しない。一方、厳密に定めた有限事象集合が空なら、その領域内で確率0と判断できる。

反復数30は**初期パイロット**として採用する。20〜30回で高精度の成功率推定が完成すると主張しない。

以下の95%安定取得や30/60反復は研究上の採用基準案であり、現在の実装について保証された性能や、承認済みの本実験条件ではない。

- 全計画30/30成功でも、成功率の片側95% exact下限は約90.50%。95%以上の安定取得を証明するには足りない。
- 選定後の新seedで60回を確認し60/60成功なら、片側95%下限は約95.13%。失敗がある場合はexact下限で判断し、不成功seedを入れ替えない。
- 成功率付近0.5の両側95%区間で半幅約5ポイントを狙うなら約385反復が目安。必要な精度によってはこの予算は過大なので、取得確率を選定基準として本当に必要かを事前に決める。
- 34回路×複数事象の個別区間は記述用pointwise区間。全候補に同時95%の保証とはしない。主要事象を1つ事前指定し、複数の有意差検定をする場合はHolm法等を用いる。
- shots条件の選定に用いた30反復を、選定後の確認実験と同じ独立確認データとして再利用しない。

集計は固定instance上の条件別分布・可行解取得率・失敗種別を基本とする。失敗のD/Wはnull、Tは失敗までのwall時間を別列に残す。可行解だけのTや品質を報告する場合は条件付き集計と明記し、全試行の取得率と失敗時間も併記する。問題の不可行性証明と、時間内に解を得られなかったことは別状態とする。

## 計算時間と比較の公平性

系列Fでは`T_state_prepare`,`T_sample`,`T_decode`,`T_candidate_dedup`を計測し、部品時間として報告する。系列Pでは全体の`T_program`と、入力・初期解・訓練・回路構築/状態準備・最終測定・古典日列/完成・検査の時間を保存する。内部時間と親時間を二重加算しない。

`T_program = T_preprocess + T_algorithm + T_completion + T_validation`という排他的な区間分解を採る。結果ファイル出力は`T_output`へ分離する。第二独立検査も採用計画の最終判断に含めるなら、その終了を全手法共通のT終点とする。旧S1の82.3859秒は旧終点の値として保全し、新版と測定境界の差を記録する。

同じ計算機、ライブラリ版、スレッド数、プロセス条件を固定する。温まった状態の測定単体診断と、入力読込からの新規プロセス計測を分ける。状態準備・キャッシュの再利用は系列F内で明示し、全体Tの条件へ黙って持ち込まない。条件の実行順を事前に固定した均衡順序で回し、時刻・負荷・最大RSSも記録する。

元の`run_ad_experiments.py`はDの外側300秒timeoutを持つが、`run_ad_method.py`単独にはその外側制限がない。JSONの`stage_seconds`だけで全体停止が保証されるとはしない。将来ランナーで外側timeoutと段階別予算を実効値として記録する。全体時間の見通しは未測定なので、shots比で推測した実験時間は掲載しない。

## 系列O：訓練shotsの別系列

最終測定のshotsを選んだ後、必要なら訓練shots=1,000/4,096/8,192を別系列として検討する。最終shots、候補領域、p、COBYLA予算と停止条件を固定する。角度が変わるため、これは系列Fと異なる分布を学習する実験である。最終shotsのみの効果に混ぜない。訓練初期化・訓練雑音・最終測定の子系列を分け、`Σ評価ごとのshots+Σ最終shots`とwall時間を比較する。

## 採用・中止基準

1. 実効設定・counts・回路/角度hash・seed・失敗が記録されない条件は採用しない。
2. 追加価値のある候補集合が空の問題では、shots増加を性能改善策として採用しない。モデル側の領域変更を別途検討する。
3. 8,192を優先診断し、10,000の追加候補・最終品質の利益と実測追加時間を確認する。丸い数であることを採用理由にしない。
4. 16,384/32,768は、低確率だが価値のある候補を追加取得できるか、精度要求を満たすかを確認する。取得数だけでなく同じ完成器後の品質・取得率・全Tを評価する。
5. 所望の取得確率・精度を満たす中で、実測全Tの小さい条件を選ぶ。95%の安定取得を要求するなら、選定後の独立確認データの片側95%下限で判断する。
6. 品質向上がなくTだけ増える条件、または有限予算内の解取得率が落ちる条件は、より大きいNだからという理由では採用しない。時間上限・失敗を含む全結果を残す。
7. 有用候補の効果と時間の双方が未測定の現時点では、**本実験用Nはnull/HOLD**。既存4,096を統計的に保証された値としない。
