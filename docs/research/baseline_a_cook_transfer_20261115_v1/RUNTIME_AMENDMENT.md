# 実行入口の修正と失敗の保全

run01は学習モデル生成に成功したが、著者前処理が全4方式で依存パッケージ不在により停止した。CLIが仮想環境Pythonのシンボリックリンクへ`resolve()`を適用し、基底Pythonを実行していたためである。仮想環境のパスを維持する修正と依存関係の事前検査を追加した。著者コード・依存パッケージの内容は変更していない。

その後のNN参照の採点入口でも、公式scoreが期待する終点Stationを渡していない不具合で停止した。公式scoreにだけ始点Stationを終端へ再付加し、内部の一回訪問表現は維持した。この差は既存の公式scorer照合テストと整合する。2件の回帰テストを追加した。

修正前の入口を`ENTRYPOINT_BEFORE_RUNTIME_FIX.py`へ保存した。run01のモデル・失敗・プロセス・採点前提案hashは別出力に保持した。run01ではCookのソルバー推論は始まっていない。評価実績は採点入口で既に読み込まれたため、修正後の実行を「実績ファイルを一度も開かなかった完全盲検試験」とは説明しない。表示・保存された評価scoreに基づく対象変更やパラメータ調整は行っていない。

選択ID・分割・設定・計算予算を変更せず、修正後コードhashをplan04へ記録してrun02を実行する。plan02/plan03/plan04の選択IDが一致することを独立確認する。plan03は当初規約の証拠として残し、最終再現入口はplan04/run02を参照する。

初回のplan01/02の停止理由は`PLANNING_FAILURE.json`に、run01の停止理由は`RUN_FAILURE.json`と各方式の`FAILURE.json`に残している。失敗を成功回数・性能平均へ加算しない。

run02は全4方式×8ルートと再実行2件の推論を完了し、48件の指標・公式scorer照合も計算したが、照合結果のNumPy真偽値をJSONへ保存する時点で停止した。これをPythonのbool/floatへ変換し、保存済み提案のhashを検証して`finalize`工程だけを新規`finalized01`へ実行した。元のrun02を上書きせず、ソルバー探索も再実行していない。再計算した48件のMETRICS.jsonはrun02とバイト一致した。修正前の推論入口`ENTRYPOINT_RUN02.py`はplan04のコードhashと一致する。

型変換の回帰テストを追加し、最終検査は34 passedである。最終化を含む新しい入口は次回の`run`でも利用できる。本実行の推論wall総量は例外により完了値を保存していないためnullとし、全82プロセスの実測wall合計169.160975秒と、再集計58.595970秒を区別して保存した。これらをAの正式Tへ転用しない。
