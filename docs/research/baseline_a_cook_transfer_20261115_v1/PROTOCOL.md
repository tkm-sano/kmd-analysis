# Cook著者実装の少数再現・未知拠点試験

本規約は新しい評価ルートの学習・推論・採点より前に固定したものである。既存研究結果を知った状態での再現であり、完全に盲検化した事前登録ではない。初期のメタデータ確認と修正は[訂正記録](REGISTRATION_AMENDMENT.md)に残した。

対象は著者公開`heldstephan/jpt-amz`のcommit `dc4ebc0aa091d4d1eb7dc7d9b9b2d8f8c19664ce`である。2021競技版の公開実装を少数データ・明示した計算予算で実行する。2024巻号の改良論文の全件結果や、2021競技scoreの完全再現は主張しない。

## データと分割

既存Amazon evaluationキャッシュの過去履歴を、本試験専用に時系列・拠点で分割する。公式training/evaluation分割の再現ではない。新たな大規模データ取得は行わない。元データの品質ラベル・荷物属性を持たないため、High品質の学習ルートを選別した原実験とは条件が異なる。

メタデータだけでSHA256順位を定め、DLA9/DBO3各8ルート、合計16ルートの2018年6–7月履歴でモデルを作る。評価は同じ2拠点の9月以降各2ルート計4ルートと、学習から完全に外すDLA7/DLA8各2ルート計4ルートである。1日1ルートを採用する。過去に採点した全ルートID・拠点日を除いた。DLA7は過去pilotの1日だけ使用済み、DLA8は過去解析でも未使用である。

学習・同一拠点将来・未知拠点の全24 IDと日付、原本hash、seed、設定・コードhashは[固定した選択](../../../output/toc_delivery/a_cook_transfer_20261115_plan03/REGISTRATION.json)にある。配送先数30–200、元の配送先zoneが全て埋まっているルートに限定した実装確認標本である。欠測を含む全実績の代表標本ではない。選択後の入力不正・失敗も全て保存し、成功例だけで平均しない。

最初のplan02には原データのStation zone=NaNを厳密JSONへ出せない問題があった。Stationの欠測zoneだけnullへ直したアダプタでplan03を作った。著者処理は双方を欠測として扱い、配送先zoneは変えていない。plan02とplan03の選択IDは同じである。既存原本は変更していない。

## 比較する処理

|方式|処理|
|---|---|
|Cook_public_zones|著者学習モデルと実績区域IDを使う。原applyのpath版とprecedence/transitive版を生成し、著者の1%選択規則で統合する|
|Cook_no_station_history|全体から学んだclusterKeysは維持し、拠点別station_infosとsuperSetsだけ空にする。同じ実績区域IDを使う|
|Cook_auto_zones|実績区域IDを読み取らず座標の再帰中央値分割（葉12地点）で区域を作る。拠点別履歴を使わず、学習済みclusterKeysは維持する。追加研究仮定であり著者の原方式ではない|
|Cook_no_zones|著者の`-noZone -noZonePred`を使う。実績区域・拠点別区域履歴を用いない|
|NN_time|同じ履歴移動時間行列での既存最近隣処理である。大田区の道路距離NNそのものではない|
|Actual_reference|実績自身へのscore等を確認する参照である。生成器へ渡す計画ではない|

全ての入力でroute/行列/package ID写像のstop順を同じ順に揃える。著者applyと同じく`-Windows`は無効である。荷物ファイルは全stopの順序写像としてだけ使用し、各stopに空辞書を置く。架空の荷物属性・サービス時間・時間窓は加えない。この条件では著者生成器はpackage内容を制約へ使わない。

学習実績だけを著者model builderへ渡す。評価実績は、全方式の提案と再実行の提案をhash固定した後に採点側が読む。最終案の選択に評価score・実績順序を使わない。未選択の2定式化についても出力・コスト・時間を保存する。

## 計算資源と評価

CPU1コアへaffinityを固定し、native thread=1、著者LKH seed=1とする。1ルート当たり2定式化を各CPU時間2秒、各プロセスwall上限15秒で実行する。前処理上限45秒、試験全体上限900秒、外側上限960秒とする。原著の動的予算や16並列のshellを直接実行せず、同じCソルバーを順次呼ぶ。コンパイルも1コアで行い、計測と分ける。`PYTHONHASHSEED=0`、`PYTHONDONTWRITEBYTECODE=1`で実行する。

主指標は公式Amazon scoreであり、小さいほど実績順序に近い。二次指標は有向arc一致、元の区域で測る再進入、正規化Kendall逆転数、同じ時間行列による閉路移動時間/実績時間である。自動区域版も評価区域は元の区域を使う。NNとの差はルート別・拠点別に保存する。各splitは2拠点4ルートにすぎず、記述的な比較に留める。同等性許容幅は設定せず、実務同等性・母集団への有意差は判定しない。

全stop一回・Station先頭・向き保存・閉路のコスト再計算を検査する。独立実装のscoreと保存済み公式Python scorerの差を1e-10以下で照合する。1件ずつ同一拠点将来と未知拠点でfull public-zoneを再実行し、順序一致・差をそのまま記録する。実時間停止による変動を理由に良い再実行だけを採用しない。

実装合格は入力変換・著者コード実行・全件順序検証・公式score照合の成功で判断する。未知拠点でNNを下回っても、当該拠点の区域IDを与えた条件かを明示する。海外未知拠点への移転と、大田区の実績代表性を分ける。距離km・積込待機W・人手計画Tをこのデータから推定しない。本試験のwall時間は外部順序試験の時間であり、本研究のA_programの正式Tではない。

大田区の需要・OD、既存A、B/C/D、RQ・仮説を変更しない。主比較への方式採用やS1〜S3本実験は本試験に含めない。
