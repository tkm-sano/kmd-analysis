# 人手による割当・訪問順を含むAへの変更

2026-11-16。ユーザー指定に従い、人が割当・訪問順を考える作業を含む **A_human_v1** を別版として実装した。凍結済みA_rule_v1は変更しない。

## 変更内容

人が全地点の車両割当と訪問順をCSVに入力し、プログラムが容量60での最大2便分割、ready順FCFS、時刻計算と二重の物理検証を行う。人の順序を保持し、NN・角度分割・O/H改善を起動しない。共通物理条件・需要・ODは保持する。不正計画は人が修正し、棄却attemptも残す。

主Tを「未割当入力の読込前から、人手による計画作成、計算、検証、修正、最終確認と採用検査までの経過時間」とした。人手段階・機械段階・その他段階に分解し、休止も主経過から差し引かない。入力・計画・ソースのhash、同一bootの単調時計、全イベント・失敗を保存する。人手作成の申告だけで実務経験や注意配分が実証されたとは扱わない。

コード入口は[scripts/run_a_human_v1.py](../../../scripts/run_a_human_v1.py)、処理は[human_v1.py](../../../src/kmd_toc/baseline_a/human_v1.py)、設定は[a_human_v1_20261116.json](../../../configs/toc_delivery/a_human_v1_20261116.json)である。[契約](HUMAN_INCLUSIVE_CONTRACT.md)、[完成した説明文](BASELINE_A_HUMAN_EXPLANATION_JA.md)、[操作・再現手順](REPRODUCE.md)を保存した。

## 完了判定と残る条件

人手計画を入力する別方式、セッション計時、二重検証、失敗・改変・未確認の拒否、人工データの非実測扱い、説明文・再現手順は実装・限定確認済みである。実際のS1〜S3の人手計測と、BCDも同じ人手込み境界で測る比較は未実施である。旧program-only比較の参照値やJへ混ぜない。正式人手参照・Jもnullとする。

新しい人手CLIは独立入口であり、旧A〜DレジストリのAを自動的に差し替えてはいない。人手Aを含む新TでのA〜D集計入口の接続は未完了である。従来の「配送計画の計算時間」というRQ原文は保全し、新契約では人手を含む計画作成の経過時間へ定義を広げた点を説明する。

実測には担当者、使用する地図・表計算等のツールと版、経験、実施順序、全経過上限を観測前に登録し、その担当者がstartからacceptまで実行する必要がある。現行実装は一名を対象とし、複数人の並列作業の測定は未実装である。これは対象事業者の実運用・実績の再現を認定したものではない。

既存資産の照合はFINAL_AUDIT.jsonに保存した。既存コード・設定・結果、README、RQ・仮説は本作業で編集していない。commit/push、外部依頼、有料計算、正式実験、需要/OD再生成は行っていない。

開始時の既存406ファイルと凍結A7ファイルは全てhash一致した。新旧の数値・方式・契約を区別したまま保存している。
