## 2. 換算・分類

**時間の単位換算のみ**を行った。1分=60秒として、熟練者は`[5,10]×60=[300,600]`、初心者は`[30,60]×60=[1800,3600]`秒。1時間は60分に換算した。値の大小・時間幅は原文に由来し、データの内挿・外挿・統計推定ではない。中点450秒、2700秒を平均実績として作らない。

Dの13kmは原文のトラックの値をそのまま保存し、約14kmの徒歩移動と混同しない。参考としてのkm/担当車両・日は、掲載された1担当者の1日観察というscopeの表示であり、稼働台数や日数を仮定して総距離から割った値ではない。原文が営業所全体の計画を与えていないため、総距離への復元はできない。

|値の性質|対象|扱い|
|---|---|---|
|事業者公表の実測値|佐川の都市13km・郊外148km|単日事例。距離原ログ・計測器は未確認|
|事業者担当者の公表報告範囲|日本郵便の紙地図・導入後ルート作成業務|人の作業時間。標本・時計ログがないため、独立に実測確認したとは主張しない|
|単位換算値|分→秒|上記の算術だけ。範囲の意味を保持|
|行政調査の報告平均|一般貨物の荷待ち60分/運行|2025年4〜8月通常期の代表日を同年11〜12月調査。n=1032。自拠点の積込待機平均とは呼ばない|
|研究上の仮定値|積込1800秒、顧客作業120秒、準備0秒|A実績から採った数値ではない。共通条件v1.1を保持|

## 3. 補足値と不採用値

- 同じ佐川公式記事の郊外148kmは別の担当者・地域の参考例。13kmと合計161kmを一拠点の総距離にしたり、平均80.5kmを代表値にしたりしない。本文の一般的な「平均20kmほど」等も集計法不明のため主要値へ採用しない。
- 日本郵便の導入後初心者10〜15分（600〜900秒）はツール利用後の別条件。従来紙地図のA_Tと混ぜず、純粋なアルゴリズム実行時間にも読み替えない。入力、操作、確認のどこまでを含むかは未確定。
- 日本郵便事例の67分→17分は「ルート作成＋配達」の習熟度間の差。Tの絶対値・短縮値として使わない。
- 佐川2021年のLoogia実地検証にある距離9/10/11km削減とルート組み10/15/30分短縮は差分であり、D/Tの絶対水準に変換しない。資料・ドライバー区分を結び付けずに足し引きしない。
- 店舗配送の計算予算最長10分や一般的なソフトウェアの速度宣伝値を、宅配事業者のT実績として採用しない。

## 4. S1〜S3で許す表示・禁止する換算

|項目|方法|
|---|---|
|Dの参考表示|B〜Dで実使用車両数V_used>0が記録される場合に`D/V_used`を併記し、13kmの個別観察を別枠で示す。集荷・徒歩・地域差を注記する|
|登録台数での単純除算|`D/10, D/20, D/40`は未使用車両を含み得る。1実働車両の日走行とは等価でない|
|Tの参考表示|ルート作成という業務の長さを示す独立表・参考帯。入力〜検証のwall秒とは計測境界が異なることを表記する|
|W|未取得と表示。0、積込30分、全国物流の荷待ち平均を代入しない|
|一般貨物の荷待ち背景|60分を別表に出典・運行単位付きで表示。研究Wとの差・削減率・規模比例外挿を計算しない|
|S1〜S3のA値|D_km/W_min/T_sすべてnull。正式な同条件比較点を作らない|

`13×10/20/40`、荷物個数や配送先数での比例外挿、`T×車両数`、`T/配送先数`はいずれも行わない。資料にはそれを正当化する仕事量、稼働便数、固定費と変動費の分解がない。同じ需要でないため、B〜DとAの削減率・高速化倍率・パレート優越を算出しない。両方向ε制約の水準にも今回のA値を使用しない。

## 5. 未取得を埋めるために必要な情報

同条件Aの取得には、計画対象の全車両・全便・訪問先数・期間と走行ログ、各便ready/load_start、入力受付から計画確認・検証完了までの工程別時刻が必要である。事業者との連絡・データ提供依頼は今回実施していない。現状のAは外部参照としてCONDITIONAL GOであり、Wや同条件Tの取得を意味しない。

v1.1では国交省の荷待ち60分と、荷役48分・附帯14分の区別を原図で確認した。
川西倉庫30%軽減は絶対分数ではなく、別のDX報告にある70分/最大438分は分割休息混在の受付後時間なので、いずれもA_Wの補完に使わない。
海外を一律に除外せず、Amazon/LaDe/Delivering Data/工場CSV/URBANEの取得可能な項目を点検したが、
現時点で研究D/T/Wを確定する完全な原記録は取得できなかった。再構成値は実測値と別名で登録する。
