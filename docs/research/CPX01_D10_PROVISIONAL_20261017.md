## 1. 先行して正式採用された設計との関係

- **D01**：既存の4顧客・78問題を対象とし、PIDごとの固定4タスク集合で期限内需要充足率を評価する。問題間の重複訪問を独立した実需要と扱わない。
- **D02**：停車開始・時間窓・サービス時間等からモデル上のサービス完了を再構成する。技術的検証は必須。
- **D03**：モデル上の完了期限は `tw_due_seconds + service_duration_seconds`。開始期限そのものを完了期限にする比較は未採用候補。
- **D04**：量子計画取得成功64件の対応比較と、量子未取得14件に古典計画を用いる全78件の運用比較を分ける。
- **D05**：仮想計画利用可能時刻を主分析、保存計算時間を参考分析とし、古典・量子計画は並行準備する。予定出発は時刻0秒。
- **D06**：簡易時刻評価で実験条件を整理し、出発遅延後の正式評価は新しいSUMO実験を原則とする。
- **D07**：初期電力量評価は既存B0（180 Wh/kg、20 kWh）と限定的Controlled-DCを使用し、回生・補機等の拡張は別段階。2種類のCrr境界は区別する。
- **D08**：量子優先・期限付き待機。量子計画が期限内に利用できなければ古典計画へ切り替える。
- **D09**：採用期限 `t_cut = -B`。量子計画の失敗を期限前に知った場合は早期切替えを認める。`B = 0`、`B = T_dispatch`、`B = T_switch + T_dispatch` の3条件を比較する。

これらの先行決定は正式採用済みである。本書で**仮採用**するのはD10の数値水準であり、先行決定を仮採用へ格下げするものではない。

## 2. D10の仮採用時間水準

| 変数 | 仮採用値（秒） | 用途・根拠の区別 |
|---|---|---|
| `L` 事前準備時間 | **900, 3600, 7200** | 予定出発15分・60分・120分前から並行準備する仮想条件 |
| `T_C` 古典計画仮想取得時間 | **120** | 初期分析で固定。古典計算の実測値ではない |
| `T_Q` 量子計画仮想取得・結果判明時間 | **60, 900, 3600, 7200** | 主要操作因子。量子実機の処理時間ではない |
| `T_other,C`, `T_other,Q` | **各0** | 計算外の通信・検証等の追加遅延を初期分析では設けない仮定 |
| `T_switch` 古典計画への切替時間 | **600** | 初期分析で固定。事業者の実測時間ではない |
| `T_dispatch` 計画採用後の出発準備時間 | **120** | 初期分析で固定。事業者の実測時間ではない |
| `B` 量子計画の締切余裕 | **0, 120, 720** | D09の3条件にそれぞれ対応（後2者は他の仮採用値から決まる） |

`L(3) × T_Q(4) × B(3) = 36` 通りの時間条件を、既存4顧客R1の78問題へ対応付ける。**論理的な運用評価は 36 × 78 = 2,808 条件**であり、SUMO実行回数や独立な統計標本数ではない。内訳は取得成功64件 × 36 = 2,304条件、未取得14件 × 36 = 504条件。64件と78件の分析を独立標本として加算しない。

## 3. 計画取得・採用・出発の暫定規則

時刻単位は秒。予定出発時刻を0秒とする。

```text
t_request = -L
t_C = -L + T_C + T_other,C
t_Q = -L + T_Q + T_other,Q
t_cut = -B
```

量子計画の保存済み取得状態（成功64件／未取得14件）は固定し、`T_Q` は結果の仮想判明時刻として割り当てる。量子計画取得成功時は `t_Q <= t_cut` なら採用し、期限超過なら古典計画を採用する（等号は期限内）。取得失敗時には、`t_Q` を仮想的な失敗判明時刻とし、`t_fallback = min(t_Q, t_cut)` に古典計画への切替えを判断する。取得成功だが期限超過の場合は `t_fallback = t_cut` とする。失敗が判明する前に早期切替えを行ったことにしない。

```text
古典のみを利用する基準条件:
    t_depart_C = max(0, t_C + T_dispatch)

量子計画を採用した場合:
    t_depart_Q = max(0, t_Q + T_dispatch)

古典計画への切替えの場合:
    t_depart_F = max(0, max(t_C, t_fallback) + T_switch + T_dispatch)
```

古典計画と量子計画は並行準備でき、切替時間と出発準備時間は非重複で順次加算すると仮定する。計画の利用可能時刻が早くても、基準条件では予定出発時刻0秒以前に出発しない。これらの運用規則が実事業者で採用されているとの主張ではない。

## 4. 出力・解析・実行条件

運用規則の条件展開では、少なくとも `PID`, `parent_id`, `replicate_id`, `L`, `T_C`, `T_Q`, `B`, `t_C`, `t_Q`, `t_cut`, `quantum_acquired`, `adopted_method`, `fallback_reason`, `t_fallback`, `t_depart`, `departure_delay_s` を記録する。取得数と実際の計画採用数を区別する。

保存済みの古典・量子訪問順、同一PIDの対象4タスク、時間窓等を使用する。D02の技術検証が完了した場合に限り、D03のモデル上の完了期限に基づいてPID別の期限内充足率を算出する。新規SUMO走行軌跡のエネルギー評価にはD07の限定的B0・Controlled-DCを適用し、完全な走行時正味DC電力量と混同しない。

現行の仮採用水準では、出発遅延候補が概ね **0, 120, 600, 720秒** に集約される見込みだが、これは計算規則の事前分析であり、全条件の機械検証を要する。SUMO実行の重複削減は、PID・採用訪問順・出発時刻・道路・車両・停車条件・実行条件の同一性を確認して判断する。同じ出発時刻でも計画が異なれば同一走行とみなさない。

時間条件は実験後の結果に合わせて選び直さない。必要な見直しは主分析前に版を更新して明示する。**差が生じない条件も結果として扱う。**

1. 既存の古典 `phases.* / worker_wall_s` と量子 `wall_s / sampling_wall_s / PROCESS.wall_s` の計測範囲を区別し、既存の時間分布を参考情報として確認する。仮想的な値を実測値や将来量子機の性能値へ読み替えない。

3. 36条件×78PIDにおける量子採用・失敗判明・古典切替え・出発時刻の論理整合を確認する。
4. 既存出発時刻0秒のSUMO基準条件と新規実行環境を照合し、時間窓待機、停車制御、専用SUMO実装の依存関係を検証する。
5. 新規走行軌跡がControlled-DCの入力契約と評価区間を満たすか確認する。
6. 条件展開後のSUMO実行ケース数、反復回数、推論・集計方法、実際の計算環境と必要工数を別途決定する。
