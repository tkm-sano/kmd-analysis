# 配送計画の作成時間に関する現場課題のデスクトップリサーチ

調査日：2026年11月11日。修士論文の研究背景に用いる、配送計画の作成・再作成に関する根拠を整理した報告書である。

**確認できた結論は、即日配送や配送中の状況変化に応じる業務では、業務制約と配送効率を考慮した計画を短時間で作成・更新することが課題となる、という条件付きのものである。** 国内宅配には状況変化に応じた再計算の導入例があり、査読論文には翌日配送と即日配送の計画時間の違いが明記されている。ただし、国内ToC配送全体に共通する秒・分の許容時間や、量子計算の必要性・一般的な高速性までは確認できない。［[S08](https://www.optimind.tech/news/ルート最適化システム「loogia」を佐川急便で導入を/)、本文「今回の取り組みは」；[S06](https://doi.org/10.1002/nav.21954)、§6.6、pp.738–739］

## 第1章 調査目的・対象・方法

### 1.1 目的と対象

目的は、配送計画の現場課題を第三者に一文で説明でき、その主張を原文の掲載箇所へ追跡できる状態にすることである。「短時間で計画を作成・更新することが求められる」という仮説を検証対象とし、量子利用を前提とせず調査した。本研究のRQ、評価指標、課題と評価指標の因果関係は検討対象に含めない。

日本国内のToCラストマイルを優先した。ただし、現場で明示された計算時間上限や量子比較の資料は店舗配送、拠点間輸送、静的ベンチマークにも広げた。各事例の対象業務を証拠一覧に記録し、他業務の数値を国内宅配の性能要件に転用しない。

### 1.2 検索と原文確認

指定された6文献を最初に確認し、その引用文献・関連研究と、日本語・英語の追加検索から資料を収集した。J-STAGE、出版社サイト、著者・大学の公開稿、企業公式サイト、省庁PDFを用いた。主な検索語は「自動配車 計画作成時間」「配送 ルート最適化 コープ 立案 時間」「quantum vehicle routing classical benchmark time seconds」「dynamic vehicle routing real time optimization」「Clarke Wright scheduling vehicles central depot」「Hybrid genetic search for the CVRP」等である。実施した検索と採否は別添[search_log.md](search_log.md)に示す。

Google Scholarの直接検索、有料データベースの網羅検索、非公開の運用資料の照会は実施していない。検索結果の要約を文献発見に用いたが、採用する数値は論文本体または発行主体の原文で確認した。取得できたPDF・HTMLと抽出テキストを同じフォルダの `sources/` に保存した。Clarke–Wright原著はブラウザで本文を確認したものの、ローカルのPDF取得には至らなかった。

査読原著、学会論文、企業技術論文、公的資料、企業公式報告を優先した。最終的に15件を証拠一覧に収録し、11件を採用、4件を補助とした。「採用」は当該資料が述べる全ての主張への同意を意味せず、各欄に示した用途に限る。Liuらの総説は文献発見と限界整理に用い、他研究の数値を総説から転載しない。［[S05](https://doi.org/10.3390/smartcities8060206)、§§3、5–6、表A2］

### 1.3 時間と証拠の区別

| 区分 | 本報告書での意味 | 誤って同一視しないもの |
|---|---|---|
| 人を含む計画業務時間 | 地図確認、入力、確認・修正などを含む作業時間や期間 | アルゴリズムの実行時間 |
| 計算の設定上限 | ソルバーに与えた時間予算・停止条件 | 実測平均、最適解に必要な最短時間 |
| 初期解到達時間 | 最初の解が得られるまでの報告時間 | 同品質の最良解に到達する時間 |
| 計算部分の時間 | ソルバー、アニーリング、QPU access等の時間 | 前後処理・通信・待ち行列を含む総時間 |
| プログラムの総時間 | 著者が計測対象とした処理全体の時間 | 現場のデータ準備から計画配信までの業務全体 |
| 配送時間・車両稼働時間 | 作成した計画の実行に要する時間 | 計画を計算する時間 |

また、量子実機、古典機上の量子回路シミュレーション、量子インスパイアード計算を分ける。シミュレーションの成果を現場導入の効果としない。以下の表は各文献内の比較を示し、異なる問題・環境間の速度順位は算出しない。

## 第2章 配送計画の現場課題

### 2.1 国内ToCで確認できた作成と更新の課題

佐川急便とオプティマインドの共同発表は、出発前にドライバーが行う集配先の位置確認・ルート決めを自動化し、配達進捗や再配達に応じてルートを再計算する仕組みを説明している。実地検証・試験導入を経た導入発表であり、国内宅配において計画作成支援と状況変化への対応が実際の開発・運用課題となった根拠である。本文はルート組み時間の短縮を報告するが、計算遅延の秒・分の実測値は示さない。「リアルタイム」という表現を一定秒数の保証に読み替えない。［[S08](https://www.optimind.tech/news/ルート最適化システム「loogia」を佐川急便で導入を/)、本文第2段落、「これまでの取組実績」1・2］

コープさっぽろの公式インタビューでは、加入・脱退に伴うコース調整が積み重なり、数年に一度の大規模再編である「大改廃」に、職員総動員で約3か月を要していたと述べる。これは国内ToC事業者自身が述べる負担であるが、コース再編プロジェクトの期間であり、日次配車の計算時間ではない。現場との適合や人の確認・修正も課題として挙がる。［[S15](https://dx.sapporo.coop/n/ne16fcf719143)、「脱属人化！ AIを活用した経路最適化プロジェクト」「あえて100点を目指さない戦略が成果につながった」］

### 2.2 開発企業が述べる計算の長時間化と変更の難しさ

住友電工の技術論文は、多数車両・多量荷物の計画計算に時間を要するため前夜に計画する運用と、出発後の渋滞・災害への対応を現場ドライバーに任せることが多い状況を説明する。交通・気象変化時の迅速な計画変更を課題とし、配送先の時間帯、車種、混載、休憩等の制約を示す。これは開発・販売実績を持つ企業の技術的問題提起である。ただし、その緒言は事業者数・分布・計測手順を伴う実態調査ではなく、「国内宅配全体で計算が遅い」という頻度の推定には使えない。［[S01](https://sumitomoelectric.com/jp/sites/japan/files/2023-01/download_documents/J202-19.pdf)、p.91 §1、p.92 §4・図1］

### 2.3 明示的な時間制約と人手作業の長さ

### 2.4 翌日配送と即日配送の違いと反対側の証拠

Schubertらは、対象とする小売配送では、翌日配送は注文が遅くとも前夜に既知であるため1時間ないし数時間の計算が重大な問題とならない一方、即日配送では計画期間が短く同じ扱いはできない、と明記する。これは仮説の適用範囲を限定する主要な査読根拠である。同論文は大型消費財の宅配・設置等を対象とし、受注締切後のピッキングと配送を統合する静的計画である。即日配送であることと、運行中の新規注文を逐次処理する動的配送であることは同義ではない。［[S06](https://doi.org/10.1002/nav.21954)、p.723 §2.1・図1、pp.738–739 §6.6］

また、配送先や需要がほぼ変わらなければ、初回の計画を繰り返し利用できるとの技術的説明もある。迅速性の必要度は、情報が確定する時刻、出荷・納入期限、変更頻度に依存すると解釈できる。この依存関係は以上の資料を統合した判断であり、国内全事業者の定量調査結果ではない。［[S14](https://www.oki.com/global/ja/technologies/otr/assets_c/uploads/otr241_r05.pdf)、p.32「配送ルート最適化」］

### 3.2 古典計算の速さと解品質

Schubertらの比較では、5注文でCPLEXの最適解到達は平均0.25秒、i_GVNSの最終解到達は平均0.01秒未満である。7注文ではそれぞれ24.63秒と0.03秒であり、i_GVNSは小規模540例中530例で最適解に達した。これらはアルゴリズムの実験値である。50・100・200注文に設定した5・10・30分は別の時間予算であり、「その時間がなければ計画を出せない」ことを意味しない。［[S06](https://doi.org/10.1002/nav.21954)、pp.731–733 §§6.3–6.4、表5］

Vidalの著者公開稿では、100–1000顧客の標準CVRPに対して、Intel Gold 6148、1スレッドの共通環境で各手法を10回実行し、時間上限を顧客数に応じて4–40分に設定している。上限時点の平均BKS乖離はHGS-CVRPが0.11%、OR-Toolsが4.01%である。この結果は、古典計算にも高品質な実装があり、速度を論じるには品質と計測条件が必要であることを示す。BKSは既知最良解であり、ここでの乖離を最適性の証明に対するgapとはしない。数値は出版社最終版と対応する著者公開v2で確認した。［[S10](https://arxiv.org/abs/2012.10384v2)、§5、pp.11–15、Table 2］

実運用に近い例では、OKIの分割配送ツールはPython3、Gurobi 9.1、3.1 GHz・4コアのクラウド計算機を用い、最長10分の計算予算で店舗配送の計画を作成した。これは現場の時間枠内で古典数理最適化を用いた実証である。人手計画との走行距離比較は異なる日の実配送データに基づくため、同一注文・同条件の対照試験としては扱わない。［[S14](https://www.oki.com/global/ja/technologies/otr/assets_c/uploads/otr241_r05.pdf)、p.34「配送ルート最適化ツール」「実証実験」・図3］

### 3.3 再計画の迅速性と事前計算

Klappらの著者公開稿では、50注文に対し、greedy方策GPのオンライン意思決定当たりの平均時間は0.06–0.16秒、rollout方策RPは147–305秒である。事前計算1689–2084秒は別枠である。Xeon E5620の1スレッド、Java、CPLEX 12.6を用いた実験であり、速い簡素な方策と、より多くの計算を行う方策が比較されている。RPの費用改善は確認されるが、GPと同一品質に達する時間の比較ではない。これらの数値は2017年5月23日の著者公開稿で確認したため、2018年出版社最終版の数値として断定しない。［[S11の確認稿](https://bpb-us-e1.wpmucdn.com/sites.gatech.edu/dist/7/1474/files/2020/09/DDWP2D.pdf)、p.14 §6、pp.16–17 Table 2、p.20 Table 3］

実用上の更新については、佐川急便の導入例が配送中の進捗・再配達に応じた再計算を示す。したがって、迅速な更新への対応は量子計算に限定された研究課題ではなく、古典手法と商用システムの双方で取り組まれている。後半は本調査で確認した研究・事例の総合判断である。［[S08](https://www.optimind.tech/news/ルート最適化システム「loogia」を佐川急便で導入を/)、本文］

## 第4章 量子計算への期待と比較研究

### 4.1 期待されている内容

量子関連研究が目指すものには、制約の多い大規模問題の探索時間短縮、限られた時間内での解品質改善、扱える問題規模の拡大がある。例えば、S02は初期解の高速生成、S03は実規模の制約下での量子回路を含む学習・探索の成立性、S01は複雑な配送制約のQUBO表現と解品質の検証に重点がある。これらを同じ「量子による高速化実証」と一括りにしない。［[S02](https://doi.org/10.11517/pjsai.JSAI2023.0_2J4GS103)、§§1、4–5；[S03](https://www.aisin.com/jp/technology/technicalreview/30/pdf/all.pdf)、§§1.3、3、7–8；[S01](https://sumitomoelectric.com/jp/sites/japan/files/2023-01/download_documents/J202-19.pdf)、§§1、7–8］

論文では、量子重ね合わせ、量子アニーリングによる探索、量子回路の表現・学習挙動等を動機として挙げる。しかし、量子状態を多数表現できることから、この配送問題で所望の品質の解を古典より短時間で出せるという結論は導かない。期待の評価には、前後処理を含む計測範囲と古典ベースラインの確認が必要である。S12の実験とS05の総説が、その区別の必要性を示している。［[S12](https://doi.org/10.3389/fict.2019.00013)、§§5.2.3、6；[S05](https://doi.org/10.3390/smartcities8060206)、§§5.3–6］

## 第5章 総合評価

### 5.1 短時間での作成・更新は実際の課題か

**条件付きで肯定できる。** 国内宅配の導入例は、出発前作業の支援と、配達進捗・再配達による再計算を示す。国内店舗配送の実証には、業務上の計算時間上限もある。ただし、前者は秒単位の遅延を測っておらず、後者はToCではない。両者を合わせても、国内ToCでの計算遅延の発生率や共通の許容秒数は定まらない。［[S08](https://www.optimind.tech/news/ルート最適化システム「loogia」を佐川急便で導入を/)、本文；[S14](https://www.oki.com/global/ja/technologies/otr/assets_c/uploads/otr241_r05.pdf)、p.34］

### 5.2 どのような業務条件で重要か

即日配送のように受注確定から出荷・納入までの余裕が短い場合、また、配送中の進捗・再配達等で計画の更新が必要な場合に重要である。一方、前夜に注文が確定する翌日配送や、同じ計画を反復利用する固定的な配送では、同程度の即応性が常に必要とは限らない。ここから支持されるのは「業務上許される時間内」という要求であり、「あらゆる条件下で計算時間だけを最小化すべき」という要求ではない。［[S06](https://doi.org/10.1002/nav.21954)、§6.6；[S08](https://www.optimind.tech/news/ルート最適化システム「loogia」を佐川急便で導入を/)、本文；[S14](https://www.oki.com/global/ja/technologies/otr/assets_c/uploads/otr241_r05.pdf)、p.32］

### 5.3 どのような対応が研究・実用化されているか

古典計算では、迅速な構成法、局所探索・メタヒューリスティクス、数理最適化、事前計算とオンライン更新の組合せ、および商用自動配車が確認できる。量子関連では、エリア分割、QUBO表現、量子回路を含む機械学習等が検討され、特定の初期解や特定の比較構成で改善報告がある。これらは第3・4章の各比較と掲載箇所から追跡できる。

### 5.4 事実と期待の境界

| 確認されたこと | 今回の根拠で確認できないこと |
|---|---|
| 計画作業の長さと更新への対応が課題となった個別事例がある | 国内ToC全体の計画遅延の分布・共通許容時間 |
| 古典計算で短時間の構成や実運用の再計算に対応する例がある | 現行古典技術全般では要求を満たせないという主張 |
| 特定の量子ハイブリッド・シミュレータを含む手法に改善報告がある | 量子実機が最良の古典手法より一般的に速いという主張 |
| 総時間で古典が速い実験、量子を含む手法の品質がBKSに及ばない実験がある | 実務規模・同品質・同条件での量子の普遍的優位・劣位 |
| 将来の規模拡大・品質改善への期待が述べられている | 期待を実配送現場の実証済み効果とすること |

上表の左列はS07・S08・S14、第3章、第4章の比較に対応し、右列はそれらの対象・計測範囲から導く本調査の採用限界である。量子計算への関心が存在することと、現場課題の解決に量子計算が必要であることを分けて結論する。

## 第7章 調査の限界と未実施事項

1. 国内ToCの時間に関する公開一次資料は、共同発表や担当者インタビューが中心である。秒・分単位の計算時間と品質・規模・環境を揃えた国内宅配の現場計測は、今回の採用資料では確認できなかった。
2. BtoB店舗配送、拠点間輸送、大型消費財の宅配、静的CVRP等を補完的に用いた。これらの時間上限や速度を国内ToC全体へ一般化していない。
3. 新規注文については動的配送の一次研究S11を確認した。交通・気象変化については開発企業S01の課題説明を確認したが、国内ToCでそれらの変化に対する再最適化の遅延と現場効果を同時に測った査読研究までは確認していない。実用例S08の明示的な更新要因は配達進捗・再配達である。
4. 即日・翌日の差はS06の対象業務における査読論文の議論である。即時配送・フードデリバリー全般に共通する計算時間の数値要件は確定していない。
5. Clarke–Wright原著のローカルPDF保存は未達である。VidalとKlappの数値は著者公開稿で確認しており、出版社最終版との全文差分照合は未実施である。証拠一覧には版と確認範囲を明示した。
6. 企業発表は導入側・開発側の選択的報告を含み得る。無作為な事業者調査ではなく、課題の頻度・業界代表性は推定できない。公的事例集も独立した統制実験とは限らない。
