# A_human_v1採用仕様

A_human_v1は「研究条件下で人間が作成した配送計画」である。人間が全地点の割当と各車両の訪問順を決め、プログラムは60単位ごとの最大2便分割、FCFS、時刻計算、物理検証を行う。NN、角度分割、境界移動、局所探索、OR-Toolsによる人手決定の改善は実行しない。120地点を超える車両、欠落、重複、非連続sequence、不正IDは自動修復せず棄却する。

新しいhuman_inclusiveモードはA_human_v1を呼ぶ。legacy_program_onlyは旧比較CLIを呼び、A_rule_v1を指す。registryのラベル、implementation_id、method_version、契約と設定・ソースhashを保存する。旧記録を改名しない。

|判定|必要な証拠|
|---|---|
|IMPLEMENTED|コード・共通評価・計時・検証試験が成立|
|MEASURED|人工入力以外の人間の割当・順序・確認と時間が観測され、採用計画が検証済み|
|COMPARABLE|上記に加え同じcaseでA/B/C/Dの観測記録が同じ契約で揃う|
|formal_adoption|phase=formal、全登録試行の記録が揃い、7条件が全てPASS|

7条件は、(1)人手の割当と順序、(2)物理可行性、(3)実測、(4)同じ計時境界、(5)追跡可能性、(6)登録設計に応じた統計評価可能性、(7)限定された研究上の位置付けである。人工テストは実測条件のPASSにならない。実測がない場合はNOT_TESTEDであり、実績との不適合というFAILにしない。

adoptionは同じケースが観測されていることと、比較対象全試行の記録が揃うことを確認する。成功値の比較はaggregateの対応ケース表を併用する。少数の記述的比較を可能としても、母集団へ一般化できるとは判定しない。対象事業者の実務代表性は独立にNOT_TESTEDとする。実測担当者の計画経験・ツール・習熟度を記録しても、それだけで事業者の実務代表性は得られない。

実装はanalysis.adoption、CLIのadoptである。手続きとしてのIMPLEMENTEDと、実データによるMEASURED/COMPARABLEを明確に分ける。現時点の正式採用は認めない。
