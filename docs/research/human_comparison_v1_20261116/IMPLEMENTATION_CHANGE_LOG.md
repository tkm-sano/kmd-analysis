# 変更理由と範囲

全て新しいhuman_comparison_v1系列へ追加した。既存A_human_v1のcomplete_manual、A_rule_v1、BCDの候補生成・目的関数・設定は変更していない。

|追加|理由と影響|
|---|---|
|contract.py / formal_template|担当者、需要系列、上限、反復単位、実行許可、RQ承認を未指定のまま実行させない|
|session.py|入力開示前から採用までのTtotal、排他的活動区間、棄却・修正・休止、期限、プロセス木の後始末|
|machine.py|元方式を新規プロセス内で呼び、BCD全枝とD各処理を観測。追加記録の負荷も計時に入る|
|evaluation.py|全方式の共通物理・独立指標検査、Aのみ手入力保持とFCFSを照合|
|inputs.py|将来の複数需要bundleを共通物理条件のまま受け入れる。既存需要・ODは再生成しない|
|analysis.py|証拠照合、全試行表、primaryのケース対応、適格なCI、段階別採用判定|
|新CLI・RESULT_SCHEMA|明示モード、型・null・契約を区別し、旧入口を保持|

開発検証25件、拡充38件のログを残した。その後、pauseの開始が人手へ分類されないよう修正し、compute区間と実行記録の照合、資源契約照合、比較ペア重複の拒否を追加してから、137件の回帰と8件の追加検査を実行した。人工12地点の実経路確認path01後に、コントローラ整合確認・最終採用の一部がOTHERへ分類される問題を修正し、同じ入力・設定・上限で別experimentのpath02を実行した。設定を性能に合わせて変更していない。修正前の試行、事後の無関係な共有ソース更新に対するhashガード拒否、隔離snapshotによる検証を全て保全した。最新ソースの追加回帰はTEST_05.logに記録する。

RQ案1のユーザー承認はRQ_APPROVAL.jsonに保存し、RQ_ADOPTED_V1.mdを別版で作成した。旧RQ・方向仮説・READMEは書き換えていない。監査文中の誤ったrule_worker.py参照は、実在するrun_a_rule_v1.py内workerへ訂正した。コード・実験履歴を文書へ合わせて変更していない。
