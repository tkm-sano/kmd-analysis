# 配送計画研究の作業方針

## B〜DのCPU並列処理（2026-11-13ユーザー指示）

- 今後の通常のB/C/D実行はCPU並列を既定とする。現行方式は各手法内の4プロセス並列マルチスタート。B/C/D同士は計時中に同時実行しない。
- 既定設定は `configs/toc_delivery/dwt_balance_v1_4_cpu_parallel.json`、実行入口は `scripts/run_dwt.py` / `scripts/run_dwt_bundle.py`。CPU数変更は全手法共通の明示設定で行い、割当不足を黙って逐次処理に落とさない。
- 各枝を1コア・native solver 1 threadに制限し、親の入力読込から全枝停止、候補選択、最終二重検証までのwall timeをT_programとする。共通ライブラリ/待機プロセスの準備・出力時間は別記する。
- 全枝のseed、PID、affinity、成功/失敗、D/W、計算時間、量子処理を保存する。内部枝を独立需要数や外側の反復回数へ加算しない。未選択枝の計算・shotsを隠さない。
- 旧逐次設定・旧結果は履歴として保全する。1コア再現はCLIの `--historical-serial-reproduction` を明示した過去結果の再現用途に限る。旧APIの互換経路は通常の新規実験に使わない。
- 凍結需要・既存OD・過去の実験結果を変更しない。新しい結果は別出力へ保存し、単コア版と並列版のTを同条件として混ぜない。
- 本実験や需要生成を、並列化の実装検証として無断実行しない。小規模の動作/回帰検証と本実験を区別する。README更新が明示許可されていない作業ではREADMEを変更しない。

## 共通の保全

既存の未コミット変更を保持する。研究条件・アルゴリズム・設定の変更理由と検証範囲を記録する。commit/pushは明示指示がない限り行わない。
