更新日: 2026-08-23

- `20260823`: 初版作成日（年月日）

- `研究全体構造と作業管理規則`: 文書内容

状態の意味:

- `COMPLETE`: 定義した終了条件を満たし、本線の次工程から利用できる。
- `CURRENT`: 現在の主作業位置である。
- `PARTIAL`: 一部は利用できるが、工程全体の終了条件は満たしていない。
- `NOT STARTED`: 本作業には未着手である。
- `BLOCKED`: 必要な入力、判断または外部条件がなく進めない。

## 0-1. 社会科学としての問い

中心問いは、将来の人口・世帯・物流技術・車両技術・計算技術等の条件が変化したとき、
ラストマイル配送需要の充足、配送時間・遅延・エネルギー使用、必要な最適化問題規模と計算資源が
どのように変化するか、また古典計算と量子・量子古典hybrid計算の適用可能性がどの条件で変わるかである。

道路属性を完全に復元することや、停止件数をゼロにすること自体は研究目的ではない。

## 0-2. 研究設計

同じ将来条件から、配送需要、配送条件、道路・交通状態、配送simulation、配送最適化問題、
計算手法比較までを一貫して生成する。比較対象間では、問題、道路、需要、制約、交通条件、乱数を
可能な限り共通化する。

観測値を使った調整と、その結果の確認に同じ観測を重複使用しない。現在の交通状態設計では、
国土交通省R3と警視庁2023を較正用、警視庁2024を時間的な独立確認用としている。

## 0-3. 方法論

少なくとも次を区別する。

1. 元資料から直接分かる観測
2. 仕様に基づく意味解釈
3. 内部表現
4. シミュレーションへの具体化
5. 研究目的に対する利用可否

観測で決められない値を使う場合は、元データを変更せず、`model_assumed`として由来、適用条件、
版、シナリオ、不確実性を保存する。明示的な矛盾には自動補完を適用しない。

## 本線と派生ルート

- 主要工程は `1`〜`6`、細分工程は `1-1`、`1-2`のように表す。
- 本線から派生する調査・検証は、親工程に `-A`、`-B`、`-C`を付ける。
- 例: `2-2-A`は、交通状態の観測断面固定から派生した調査である。
- 派生ルートは、分岐理由、入口条件、終了条件、本線への復帰先を必ず記録する。
- 親番号を決められない作業は開始しない。まず研究設計上の位置を決める。

## Markdownファイルの命名規則

研究作業で新しく作るMarkdownファイルは、原則として次の形式にする。

```text
ナンバリング_作成日付_STATUS_内容.md
```

例:

```text
2-2_20260823_CURRENT_SUMO観測断面対応.md
2-2-A_20260824_COMPLETE_検出位置候補調査.md
3-2_20260901_PARTIAL_将来シナリオ設計.md
```

規則:

1. ナンバリングは本書の研究工程番号または派生番号を使う。
2. 作成日付は初版作成日の `YYYYMMDD` とし、更新のたびに変更しない。
3. `STATUS`は `COMPLETE`、`CURRENT`、`PARTIAL`、`NOT-STARTED`、`BLOCKED` のいずれかとする。
4. 内容部分は日本語を基本とし、短く具体的にする。必要な固有名詞だけ英字を使う。
5. 状態が変わってファイル名を変更した場合、参照リンクも同じ変更で更新する。
6. `README.md`、`AGENTS.md`、外部ツールが固定名を要求する文書は例外とする。
7. 過去の証拠文書は、履歴を壊す一括改名をしない。新規文書から適用する。

## 作業開始時の必須記録

```text

```

日本語で意味を先に説明し、必要な場合だけ正式な英語識別子を併記する。

## 作業終了時の必須記録

```text
What was learned:
What was decided:
What remains unresolved:
Whether this branch is closed:
Where we return to in the main route:
```

## 今回の管理規則導入の記録

- `Current location`: `0-2-A 研究作業構造の管理規則`
- `Parent research stage`: `0-2 研究設計`
- `Research question addressed`: 個別作業を研究目的・依存関係・終了条件へどう接続して管理するか。
- `Why this task is necessary`: 技術的な小課題が本線から独立して増殖することを防ぐため。
- `Main route / Branch route`: 派生ルート。実証分析ではなく研究管理方法の整備である。
- `Entry condition`: 六つの主要工程と開始・終了時に必要な記録項目が指定されたこと。
- `Exit condition`: 全体図、番号規則、状態、開始・終了テンプレート、復帰先が正本へ記録されること。
- `Next destination`: `2-2 SUMO上の観測断面・検出位置固定`。

終了記録:

- `What was learned`: 既存進捗文書には研究目的と現状はあったが、全作業共通の番号・分岐・復帰規則がなかった。
- `What was decided`: 本文書の三層・六工程・派生番号・状態表示を今後の共通規則とする。
- `What remains unresolved`: 0-1の社会科学的仮説、主要評価変数、因果的主張の範囲は今後さらに明文化する必要がある。
- `Whether this branch is closed`: 完了。規則の運用は継続する。
- `Where we return to in the main route`: `2-2 SUMO上の観測断面・検出位置固定`。
